Signals

@fiorejs/signals binds values to fiorejs elements, so only the places that use a value update when it changes. This page covers the primitives, when effects and bindings run, lists, conditions, loading data and cleanup.

Source of truth: packages/signals/src

Overview

A signal holds a value. Bind it to a property, an attribute or a child of a fiorejs element, and only that place in the DOM updates when the value changes: nothing re-renders and nothing is diffed. Signals carry the live-value method that fiorejs looks for, so there is no setup step. 

import { div, button, span } from 'fiorejs';
import { state, computed } from '@fiorejs/signals';

const count = state(0);
const double = computed(() => count.get() * 2);

document.body.append(
  div.attrs({ class: computed(() => (count.get() > 5 ? 'many' : 'few')) }).create([
    button.on({ click: () => count.update((n) => n + 1) }).create('+1'),
    span(count),
    span(computed(() => ` doubled: ${double.get()}`)),
  ]),
);

A write applies at once, so count.get() and every computed that reads it return the new value. The effects and bindings that read it run again later, together, in one flush on a microtask.

Install and imports

npm install fiorejs @fiorejs/signals

The package is ESM and has one entry point, @fiorejs/signals, with these exports:

ExportWhat it does
state(value)A value you read with get() and write with set, update or mutate.
computed(fn)A value derived from other signals, cached and recalculated after an input changed.
effect(fn), effect.pre, effect.postRuns fn now and again after a signal it read changed.
flush(), tick()Runs the waiting effects and bindings now, or waits for them.
root(fn)Gives what fn creates an owner of its own and returns the function that stops it.
untrack, read, isSignalRead without subscribing, unwrap a signal or a getter, test for a signal.
classList(entries)A class name built from strings and conditions.
resource(source, fetcher)A value loaded asynchronously, with loading and error signals.

Every signal also has computed, with, map, for, if and case as methods.

state

state<T>(value: T): State<T>

A value you can read and write. Reading it with get() inside an effect, a computed or a binding subscribes to it.

MethodWhat it does
get()Returns the value and subscribes the running effect, computed or binding.
set(value)Sets the value. Setting an equal value (Object.is) does nothing.
update(fn)Sets the value fn returns for the current one, for example (n) => n + 1.
mutate(fn)Changes the value in place and always notifies, also when fn throws; the return value of fn is ignored.
const count = state(0);

count.set(1);
count.update((n) => n + 1);
count.get(); // 2

computed

computed<T>(fn: () => T): Computed<T>
signal.computed<U>(fn: (value: T) => U): Computed<U>

A value derived from other signals. fn runs on the first read and again on the next read after an input changed, and it subscribes to every signal it reads, however many: 

const first = state('Ada');
const last = state('Lovelace');

const name = computed(() => `${first.get()} ${last.get()}`);
const initial = first.computed((value) => value[0]); // derived from one signal
  • A computed keeps its value while an effect or a binding reads it, also when that reader reruns for another reason.
  • Effects and bindings that read it run again only when its value changed (Object.is) or its error changed, so user.computed((u) => u.name) does not update the DOM when another field of user changes.
  • If fn throws, the error is kept like a value and thrown on every read until an input changes; a reader that catches it stays subscribed and recovers then.
  • While nothing reads it inside an effect or a binding, it does not stay subscribed to its inputs and is recalculated on every read, so it can be garbage-collected.
A computed cannot write. set, update or mutate inside fn throws. Derive the corrected value instead, for example computed(() => Math.min(page.get(), last.get())), or correct it where it is set.

signal.with(fn) passes the signal to fn and returns the result, so reusable steps read left to right: todos.with(visible).with(byId).map(row).

effect

effect(fn: () => void | (() => void)): () => void
effect.pre(fn: () => void | (() => void)): () => void
effect.post(fn: () => void | (() => void)): () => void

Runs fn now, and again in the next flush after a signal it read changed. It returns a function that stops it. If fn returns a function, that function runs before the next run and when the effect stops. 

const stop = effect(() => {
  const id = setInterval(() => console.log(count.get()), 1000);
  return () => clearInterval(id);
});

stop();

effect.pre and effect.post choose when the effect runs in a flush: before, or after, the other effects and the bindings. effect.post sees the DOM after the bindings have updated it, and its first run waits for the next flush, when the element it was created with is usually in the document. An effect, a binding or a list created inside an effect belongs to it, and stops before the effect reruns and when it stops.

untrack, read, isSignal

untrack<T>(fn: () => T): T
read<T>(value: Reactive<T> | (() => T)): T
isSignal(value: unknown): value is Signal<unknown>
FunctionWhat it does
untrack(fn)Runs fn without subscribing to the signals it reads and without an owner.
read(value)Returns the current value of a signal, a getter function or a plain value.
isSignal(value)Whether a value is a signal of this package, also from another loaded copy of it.

When things run

Effects and bindings rerun in one flush on a microtask, not inside set(). Several writes in a row cost one run of each reader, and an effect is never re-entered. Reads are fresh at all times. 

count.set(1);
count.set(2); // effects and bindings that read count run once, with 2
count.get();  // 2
  • A new effect, effect.pre or binding runs at once, so div(count) shows its value before the next line runs. The first run of effect.post waits for the flush.
  • A flush runs the effect.pre effects, then the other effects and the bindings in the order they were created, so an effect runs before the effects it created, then the effect.post effects.
  • A write during the flush is handled in the same flush, which goes back to the first phase that has work.
  • An effect stopped while it waits does not run.

flush and tick

flush(): void
tick(): Promise<void>

The DOM updates after the code that wrote the signal has finished. To read it right away, for example to focus or measure an element, call flush(), which runs the waiting effects and bindings now. In async code, await tick() waits for the flush instead; it resolves at once when nothing waits. 

submitted.set(true);
flush();
input.focus(); // the input that submitted shows is in the DOM now

Tests call flush() after their writes and before their assertions. flush() inside an effect does nothing: the running flush, or the next one, handles the waiting work.

Errors and loops

  • An effect or binding that throws is stopped. The other effects of the flush still run.
  • At its end the flush throws the first error and reports the others with reportError (console.error where that does not exist).
  • The error reaches the caller of flush() and rejects a waiting tick(); otherwise it is an uncaught error.
  • An effect that runs more than 100 times in one flush, usually because it sets a signal it reads, is stopped with an error the same way.
  • An error in the first run of a new effect outside a flush is reported.

Binding to the DOM

A signal is live: it binds to its current value wherever fiorejs takes a value. A plain function is never live; it is a callback, so a value derived from signals is a computed. 

span(count);
input.props({ value: name });
div.props({ className: computed(() => `card ${size.get()} ${theme.get()}`) });
div.props({ style: { color: computed(() => (error.get() ? 'red' : 'inherit')) } });

div.props({ className: () => theme.get() }); // wrong: assigns the function itself
  • A value inside a nested prop binds too, as style.color above.
  • Bindings start when the element is created, so a builder used as a template binds once for every element it creates.
  • A live child can be text, a node, a list of nodes or nothing.
  • A computed that builds elements owns the bindings and effects it creates: they stop before it recalculates and when nothing reads it any more.

classList

classList(entries: string | Conditions | readonly (string | Conditions)[]): Computed<string>

Builds the class text from strings, which are always on, and condition objects, whose keys are on while their value is truthy. A condition value can be a boolean, a signal or a getter, so one getter can combine several signals: 

const active = state(false);
const enabled = state(true);

div.props({ className: classList(['card', { active, disabled: () => !enabled.get() }]) }).create();
circle.attrs({ class: classList({ hot: active }) }).create();

The array takes strings and condition objects only, and Conditions stands for an object of names to booleans, signals or getters. For a class name that a signal holds, use a computed instead: computed(() => `card ${size.get()}`). A condition derived from a signal needs a getter or a computed: { disabled: !enabled.get() } is evaluated once, when the object is created.

Lists

signal.map(render: (item: T, index: number) => Node): LiveValue<Node[]>
signal.for(key?: (item: T) => unknown).map(render): LiveValue<Node[]>

signal.map(render) renders a list from a signal of an array and reuses the rows of items it has seen before, so it renders only new items. The item itself is the key, so an item replaced by a copy gets a new row. signal.for().map(render) keys rows by item.key, and signal.for((item) => item.id).map(render) by what the function returns. 

const todos = state([{ id: 1, text: 'Write docs', done: state(false) }]);

ul(todos.for((todo) => todo.id).map((todo) => li.create(todo.text)));

todos.set([...todos.get(), { id: 2, text: 'Publish', done: state(false) }]);
  • A row is rendered once, for the item it was created with. A copy with the same key reuses the row as it is, so put the fields that change in signals, like done above.
  • A key that appears more than once gets one row per occurrence. Items without a key field all get the key undefined and are matched by position.
  • A row can be a node or a fragment. render gets the item's index at the time its row is created.
  • When the order changes, only the rows that are out of place move, so a focused input in an unmoved row keeps its focus; browsers with moveBefore keep it in moved rows too.
  • If render throws, the list keeps the rows it had and stops updating, like any binding that throws.
  • A list is a live value: pass it directly as the children. Each place it is bound keeps its own rows. Inside a computed child, give it its own element: computed(() => (show.get() ? ul(todos.map(render)) : null)).

Conditions

signal.if(then: () => A): When
signal.case(match: T | ((value: T) => unknown), render: () => A): When
when.case(match, render): When
when.else(otherwise: () => B): When

A component runs once, so open.get() ? a : b in markup is read once and never switches. signal.if(then) is the live version: it shows what then returns while the value is truthy, and nothing otherwise; .else(otherwise) adds the other branch. 

div(open.if(() => Details()).else(() => em('closed')));

div(
  status
    .case('loading', () => Spinner())
    .case('error', () => em('Something went wrong'))
    .case((value) => value.startsWith('done'), () => Done())
    .else(() => null),
);
  • In case, a function is a test on the value; any other value is compared with Object.is. The first case that matches wins, and without .else nothing shows when none matches.
  • .if(then) is the case Boolean, so .if(then).case(...) works too.
  • Branches are functions, so only the shown branch is built. It is built once and rebuilt only when another case wins; count.if(...) does not rebuild when count goes from 1 to 2.
  • When the branch changes, the bindings and effects the old branch created stop. A branch that throws is built again the next time its binding runs.
  • A branch returns text, nodes or nothing. To show a live value in a branch, put it in an element: .else(() => span(user.computed(...))).

resource

resource<T>(fetcher: (value: true, info: ResourceInfo) => T | Promise<T>): Resource<T>
resource<S, T>(
source: Signal<S | null | undefined | false> | (() => S | null | undefined | false),
fetcher: (value: S, info: ResourceInfo) => T | Promise<T>,
): Resource<T>

Calls fetcher with the value of source and loads again whenever it changes. While source gives null, undefined or false, nothing is loaded; resource(fetcher) loads once. 

const userId = state(1);
const user = resource(userId, (id, { signal }) => fetch(`/users/${id}`, { signal }).then((response) => response.json()));

div(computed(() => (user.error.get() ? 'Could not load' : user.loading.get() ? 'Loading…' : user.get()?.name)));
MemberWhat it is
get()The last loaded value, kept while the resource reloads.
loading, errorSignals of the load state. error is cleared when a new load starts and when the source becomes inactive.
refetch()Loads again with the last source value.
mutate(value)Sets the value without loading, also to undefined.
  • The fetcher runs untracked and gets an AbortSignal that aborts when a newer load starts while it is still running, or when the effect or list row the resource was created in goes away. The result of an older load is ignored.
  • A failed load that nothing reads error of is also reported with reportError, so it does not go unnoticed.

Arrays and objects

A signal tracks its value, not what is inside it. Replace arrays and objects instead of changing them:

todos.set([...todos.get(), next]);          // updates
todos.get().push(next);                     // does not update
user.set({ ...user.get(), name: 'Grace' }); // updates
todos.mutate((list) => list.push(next));    // changes in place and notifies

Copying is cheap for most lists, because only references are copied; mutate is for very large arrays or objects. For deeply nested data, give the fields that change on their own their own signal.

Components and shared state

A component is a function that runs once, so pass signals to it, not their current values. Reactive<T> accepts a plain value or a signal, and read() unwraps both: 

function Price(props: { amount: Reactive<number> }) {
  return div(computed(() => `${read(props.amount).toFixed(2)} CHF`));
}

Price({ amount: 12 });
Price({ amount: total });

A signal created at the top of a module is shared by everything that imports it, for example export const user = state(null) in store.js.

Cleanup

Bindings and effects stop on their own in these cases:

  • When a computed child, an if/case branch or a list replaces content it built, the bindings inside the old content stop for good.
  • When a list drops an item, or the effect or computed around the list reruns, the bindings inside its rows stop for good.
  • When an element is removed from the document, its bindings pause; when it is inserted again, they resume with the current values. A live child among other children keeps its place between two comments, so this also works when its nodes move, for example out of a fragment.
  • Content built outside any owner, for example view = state(Home()), only pauses when a live child replaces it and it leaves the document. Build it in a computed or a root to stop it for good.

Removal and insertion are detected with a MutationObserver on the document, so elements inside a shadow root are not paused. An element that is created but never inserted keeps its bindings for as long as its signals live, unless it was created in a root that is disposed.

root

root(fn: () => void): () => void

Runs fn with an owner of its own and returns a function that stops what fn created: effects, bindings, computeds and lists, inserted or not. Reads in fn do not subscribe. 

const dispose = root(() => document.body.append(App()));

dispose(); // stops every binding and effect of the app
  • A binding stopped by its root stays stopped when its element is inserted again.
  • A root belongs to no other owner, also when it is created inside an effect, so call its function yourself.
  • If fn throws, what it created is stopped and the error is thrown.

TypeScript types

The declarations ship with the package. The exported types:

TypeDescribes
Signal<T>Any signal: get(), computed, with, map, for, if, case.
State<T>A signal with set, update and mutate.
Computed<T>A derived signal.
Resource<T>A signal of T | undefined with loading, error, refetch and mutate.
ResourceInfoThe second argument of a fetcher: { signal: AbortSignal }.
Reactive<T>A plain value or a signal of it.
When<A, B, T>The live value of if and case, with case and else.
Keyed<T>What for(key) returns, waiting for map.

Signals fit the Live<T> type of fiorejs, so props, attributes and children check the type of a signal like that of a plain value.

Limits

  • A computed that returns a nested object, such as style: computed(() => ({ color })), merges that object into the element on every update and never clears a key that disappears from it. Bind each key on its own instead: style: { color: computed(() => ...) }.
  • refetch() on a resource whose effect or list row has gone away still starts a load; call it only while the resource is in use.
  • A page that loads two copies of the package can bind signals from both, but a computed or an effect only tracks signals from its own copy.

Upgrading from 2.0

  • Effects and bindings run in a flush on a microtask, not inside set(). Code that reads the DOM right after a write calls flush() first, or uses effect.post; tests call flush() before their assertions.
  • An error of an effect or binding is thrown at the end of the flush instead of being reported, and the loop limit counts runs in one flush. A first run outside a flush still reports its error.
  • New: flush(), tick(), effect.pre, effect.post and root(fn).
