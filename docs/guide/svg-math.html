Quick start

SVG and MathML

SVG and MathML elements live in their own XML namespaces, so they have their own modules: fiorejs/svg and fiorejs/math. They work like the HTML tags, with the same builder and the same children.

SVG

fiorejs/svg exports a function for each SVG element. Each one calls document.createElementNS with the SVG namespace and returns the native element, typed as an SVGElement subtype such as SVGCircleElement: 

import { circle, g, svg } from 'fiorejs/svg';

const icon = svg
  .attrs({ viewBox: '0 0 24 24', width: '48', height: '48', 'aria-hidden': 'true' })
  .create(
    g.attrs({ fill: 'none', stroke: 'currentColor', 'stroke-width': '2' }).create([
      circle.attrs({ cx: '12', cy: '12', r: '9' }).create(),
    ]),
  );

document.body.append(icon);
console.log(icon.namespaceURI);
// http://www.w3.org/2000/svg
          
const icon = (
  <svg viewBox="0 0 24 24" width="48" height="48" aria-hidden="true">
    <g fill="none" stroke="currentColor" stroke-width="2">
      <circle cx="12" cy="12" r="9" />
    </g>
  </svg>
);

document.body.append(icon);
console.log(icon.namespaceURI);
// http://www.w3.org/2000/svg

In JSX, <svg> and the tags inside it are created in the SVG namespace, and you import nothing. On an SVG element every prop except a listener and a style object is an attribute, so viewBox, stroke-width and class are written as they appear in the markup.

SVG geometry and presentation values are attributes, so use attrs for viewBox, cx, d and fill. Hyphenated names such as stroke-width are written as they appear in the markup. Set the class with attrs({ class: '...' }), because className is a read-only object on SVG elements. The style prop works as on HTML elements.

Names that clash with HTML

JSX has no import clash, but a, script, style and title always create HTML elements, also inside <svg>. For an SVG title or a, import it from fiorejs/svg and put the node in the markup:

a, style, script and title exist in both modules, and switch is exported as switch_. When you use both, import one module as a namespace, or rename on import: 

import { a, div } from 'fiorejs';
import * as svg from 'fiorejs/svg';

const link = a.props({ href: '/' }).create(
  svg.svg.attrs({ viewBox: '0 0 10 10' }).create(svg.title('Home')),
);

document.body.append(div(link));
console.log(link.firstChild.namespaceURI, link.firstChild.firstChild.namespaceURI);
// http://www.w3.org/2000/svg http://www.w3.org/2000/svg
          
import { title } from 'fiorejs/svg';

const link = (
  <a href="/">
    <svg viewBox="0 0 10 10">{title('Home')}</svg>
  </a>
);

document.body.append(<div>{link}</div>);
console.log(link.firstChild.namespaceURI, link.firstChild.firstChild.namespaceURI);
// http://www.w3.org/2000/svg http://www.w3.org/2000/svg

The default export of fiorejs/svg is an object of all the tags, so import svg from 'fiorejs/svg' gives the same result.

MathML

JSX has no MathML tags: <math> and its children create HTML elements. Create MathML with fiorejs/math, as below, and put the nodes in JSX with braces: <p>{formula}</p>.

fiorejs/math works the same way with the MathML namespace. Its names follow the MathML elements: math, mi, mn, mo, mfrac, msup and the others. 

import { mfrac, mi, mn, mo, math, msup, mrow } from 'fiorejs/math';

const formula = math(
  mrow([
    mi('x'),
    mo('='),
    mfrac([mn(1), msup([mi('y'), mn(2)])]),
  ]),
);

document.body.append(formula);
console.log(formula.namespaceURI);
// http://www.w3.org/1998/Math/MathML

The export a of fiorejs/math is deprecated, because a is not a MathML element. Wrap the math in an HTML a, or set an href attribute.

element() per namespace

This is builder-only. In JSX the tag decides: <svg> and its children are SVG, and every other tag is HTML.

Every module exports its own element, which creates elements in its namespace. The element from fiorejs makes HTML elements, the one from fiorejs/svg makes SVG elements, and the one from fiorejs/math makes MathML elements. Use the right one for the element you want: element('title') from the HTML module is the document title, not an SVG one. 

import { element as html } from 'fiorejs';
import { element as svg } from 'fiorejs/svg';
import { element as math } from 'fiorejs/math';

const nodes = [html('title'), svg('title'), math('mi')];

console.log(nodes.map((tag) => tag().namespaceURI).join('\n'));

Each result carries a different namespace: the XHTML namespace for the first, the SVG namespace for the second and the MathML namespace for the third.

Mixing the three

Nodes from different namespaces can be children of each other, because they are all DOM nodes. An HTML page puts an svg or a math element anywhere HTML elements fit, and foreignObject holds HTML inside SVG. Create each node with the tag of its own namespace, and the browser renders it correctly. fragment is exported by fiorejs only, and it takes nodes of any namespace; in JSX the fragment is <>...</>. See Fragments.
