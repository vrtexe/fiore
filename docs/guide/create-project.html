Quick start

Create a project

npm create @fiorejs asks a few questions and writes a ready project with a small example app, a README and the tools you chose. Every question can also be answered with a flag, so it runs in scripts too.

Create the project

Run the command and answer the questions. Node.js 20.16 or later is required: 

npm create @fiorejs

Pass a folder name to skip the first question. The folder must be empty or not exist yet; the command stops with an error otherwise. When it finishes it prints the next steps for your package manager: 

npm create @fiorejs my-app
cd my-app
npm install
npm run dev

Options and flags

The questions are, in order: the project name, the build tool, the language, JSX, signals, a linter and a formatter. A flag answers its question, and the question is not asked. --yes (or -y) takes the default for every question that has no flag. The defaults also apply when the input is not a terminal.

FlagValuesDefault
--buildvite, nonevite
--templatets, jsts
--jsx, --no-jsxon or offJSX on
--signals, --no-signalson or offsignals on
--lintereslint, oxlint, noneoxlint
--formatterprettier, oxfmt, noneprettier

With npm, flags after the folder name need the -- separator, because npm would otherwise read them itself: 

npm create @fiorejs my-app -- --template js --no-jsx --linter eslint

A value that is not in the table stops the command with a message that lists the allowed values. The build tool decides what else is possible:

  • --build none is always JavaScript without JSX. --template ts and --jsx with it are errors, and the language and JSX questions are skipped.
  • --template ts and JSX need --build vite, which is the default.

A project with every answer given runs without a prompt, which suits a script: 

npm create @fiorejs my-app -- --build vite --template ts --jsx --signals --linter oxlint --formatter prettier

What the build tool gives you

  • Vite. A Vite project with dev, build and preview scripts. TypeScript templates build with tsc && vite build, so type errors fail the build. JSX uses @fiorejs/jsx as the import source, set in tsconfig.json for TypeScript, and in vite.config.js and jsconfig.json for JavaScript.
  • None. Plain ES modules with an import map in index.html that points at the files in node_modules. There is no build step, and npm run dev serves the folder with serve. Install the dependencies first, because the import map reads them from node_modules. See Installation for the idea.

The example app

Every project has a small to-do list in src/main.ts, src/main.tsx, src/main.js or src/main.jsx, with a stylesheet in src/style.css. The code depends on your answers:

AnswersThe app
Signals, no JSXBuilders and @fiorejs/signals: the list is a state, the count is derived with computed, and the rows use .for(key).map(...).
No signals, no JSXBuilders only. The code updates the DOM directly: it counts the children, toggles classes and removes the row it clicked.
JSX, with or without signalsThe same app written in JSX, which returns real DOM nodes, with or without signals.

Compare the plain and the signals version to see what signals remove: the manual updates. The Builders page explains the code of the plain version.

With JSX on, the app is in src/main.tsx or src/main.jsx, and the setting that points the compiler at @fiorejs/jsx is already in tsconfig.json or jsconfig.json for the editor and in vite.config.ts or vite.config.js for the build. JSX explains the rest.

Linter, formatter and files

The chosen linter and formatter come with their configuration and a script: npm run lint and npm run format. Oxlint and oxfmt use a .oxlintrc.json and a .oxfmtrc.json, Prettier a .prettierrc.json, and ESLint an eslint.config.js, with the TypeScript rules when the language is TypeScript. With none the files and the script are left out.

Besides the source, the project holds an index.html, a package.json, a .gitignore and a README that lists the scripts of this project. The dependency versions use the current major versions of fiorejs, @fiorejs/signals and @fiorejs/jsx.
