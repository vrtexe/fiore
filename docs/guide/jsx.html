Quick start

JSX

@fiorejs/jsx lets you write the same elements as JSX. Each JSX expression creates its elements once and returns real DOM nodes, so there is no virtual DOM and no re-rendering.

Builder or JSX

Both syntaxes create the same DOM nodes with the same signals. Pick the one you like; this page is about JSX.

Setup

New project

Run npm create @fiorejs and pick JSX, which is the default answer. There is nothing to configure: the generator adds @fiorejs/jsx to the dependencies and writes the compiler setting for you, so you can write JSX in src/main.tsx straight away. 

npm create @fiorejs my-app

For a TypeScript project it writes the setting to tsconfig.json. For a JavaScript project (--template js) it writes vite.config.js and jsconfig.json. JSX needs the Vite build, which is the default; --build none has no JSX, and --no-jsx turns it off. See Create a project for all options.

Existing project

Install the runtime next to fiorejs and tell the compiler to import JSX helpers from it: 

npm install fiorejs @fiorejs/jsx

In TypeScript, set the automatic runtime in tsconfig.json. Vite reads the same setting, but only for the files that tsconfig includes; a .tsx file elsewhere, such as in test/, is compiled for React. Set the import source in the Vite config as well, as the table below shows: 

{
  "compilerOptions": {
    "jsx": "react-jsx",
    "jsxImportSource": "@fiorejs/jsx"
  }
}

Other tools take the import source in their own options:

ToolSetting
Viteoxc: { jsx: { importSource: '@fiorejs/jsx' } } in vite.config.js or vite.config.ts
esbuild--jsx=automatic --jsx-import-source=@fiorejs/jsx

What JSX compiles to

The automatic runtime turns each element into a call of jsx, or jsxs when there are several static children, and each fragment into Fragment. All three come from @fiorejs/jsx/jsx-runtime. You can call them yourself, and the result is the same node you would get from the element functions: 

import { jsx, jsxs, Fragment } from '@fiorejs/jsx/jsx-runtime';
import { state } from '@fiorejs/signals';

const count = state(1);

// <p class="note">Clicks: {count}</p>
const note = jsx('p', { class: 'note', children: ['Clicks: ', count] });

// <ul><li>A</li><li>B</li></ul>  (several static children use jsxs)
const list = jsxs('ul', { children: [jsx('li', { children: 'A' }), jsx('li', { children: 'B' })] });

// <>text</>
const fragment = jsx(Fragment, { children: 'text' });

document.body.append(note, list, fragment);

Because the function runs once per expression, a signal in a child or prop is bound at that moment and keeps the spot up to date, exactly as in Binding to the DOM.

Props and attributes

JSX has one list of props, so the runtime decides, per name, whether to set a property or an attribute. The name decides, never the value. Names that start with on are listeners. The first letter of the event name is lowercased and the rest is kept, so onclick and onClick both listen to click, and onvalueChanged and onValueChanged listen to valueChanged. value, checked, selected, muted, indeterminate, volume, text and files are properties where the element has them, and camel-case names that the element has a writable property for, such as className or htmlFor, are properties too. Every other name is an attribute, so class, for, aria-label and width="50%" work as in HTML. 

import { computed, state } from '@fiorejs/signals';

const name = state('Ada');
const invalid = computed(() => (name.get() === '' ? 'true' : null));

document.body.append(
  <form onsubmit={(event) => event.preventDefault()}>
    <label for="name">Name</label>
    <input
      id="name"
      class="field"
      value={name}
      aria-invalid={invalid}
      style={{ width: '12rem' }}
      oninput={(event) => name.set(event.currentTarget.value)}
    />
    <img src="/a.png" alt="" title={null} />
    <button type="submit" disabled={false}>
      Save
    </button>
  </form>,
);

title={null} removes the attribute and disabled={false} leaves it out; disabled="" sets a boolean attribute, as in HTML. A style object sets style properties, and its values may be signals. A dataset object sets data-* attributes. On SVG elements every prop except listeners and a style object is set as an attribute. Full table: the package README.

Signals in JSX

A signal works as a child or as a prop value, and a derived value is a computed. A bare function is never live: class={() => …} passes the function itself, so write class={computed(() => …)}. A component runs once and returns a node, or any other child: 

import { computed, state } from '@fiorejs/signals';

function Counter(props: { start?: number }) {
  const count = state(props.start ?? 0);

  return (
    <div class={computed(() => (count.get() > 5 ? 'many' : 'few'))}>
      <button type="button" onclick={() => count.update((n) => n + 1)}>
        Add one
      </button>
      <span>{count}</span>
    </div>
  );
}

document.body.append(<Counter start={3} />);

The class of the div and the text of the span change with count. Nothing else is created again. For conditions and lists use signal.if(...) and signal.for(...).map(...) inside the markup, since count.get() > 5 ? a : b would be read once.

Fragments and children

<>...</> returns a DocumentFragment, so a component can return several siblings. Children can be nodes, strings, numbers or nested arrays; null, undefined, true and false are skipped. A live child of a fragment keeps updating after the fragment is inserted. 

import { state } from '@fiorejs/signals';

const todos = state([
  { id: 1, text: 'Write docs' },
  { id: 2, text: 'Publish' },
]);

function Term(props: { name: string; text: string }) {
  return (
    <>
      <dt>{props.name}</dt>
      <dd>{props.text}</dd>
    </>
  );
}

document.body.append(
  <dl>
    <Term name="HTML" text="Markup" />
    <Term name="CSS" text="Styles" />
  </dl>,
  <ul>{todos.for((todo) => todo.id).map((todo) => <li>{todo.computed((item) => item.text)}</li>)}</ul>,
);

In a keyed list the row gets its item as a signal, so a field is bound with todo.computed((item) => item.text) and the current item is todo.get(); see Lists.

What a component returns

A component may return a node, or anything else a child can be: a live value such as open.if(...), text, null or a list. A result that is not a node comes back in a fragment, so it renders as that child would, also when <Panel /> is appended at the top level and not placed in an element. 

import { state, flush } from '@fiorejs/signals';

const open = state(false);

const Panel = () => open.if(() => <p>Open</p>);
const Nothing = () => null;

document.body.append(<Panel />, <Nothing />);
open.set(true);
flush();
console.log(document.body.innerHTML); // <!----><p>Open</p><!---->

A component can be async. It returns a fragment with two empty comments that hold its place, and the result is put between them when it resolves, like a live child. A rejection goes to reportError. The comments stay, so a list row or a branch made of an async component keeps its place when the list changes later. 

async function User(props) {
  const user = await Promise.resolve({ name: `User ${props.id}` });
  return <p>{user.name}</p>;
}

document.body.append(
  <section>
    <h2>Profile</h2>
    <User id={1} />
  </section>,
);
console.log(document.body.innerHTML); // <section><h2>Profile</h2><!----><!----></section>
await new Promise((resolve) => setTimeout(resolve));
console.log(document.body.innerHTML); // <section><h2>Profile</h2><!----><p>User 1</p><!----></section>

Getting the element with ref

A JSX expression is typed as Node, not as the specific element. To get the element with the type of its tag, pass ref, a function that is called with the finished element, with its props, listeners and children in place. It is the same as the builder's also: 

let input;
const form = (
  <form>
    <input value="Ada" ref={(element) => (input = element)} />
  </form>
);
document.body.append(form);
input.focus();
console.log(input.value, document.activeElement === input); // Ada true

In TypeScript declare the variable with the element type, let input!: HTMLInputElement;, and the parameter of ref is typed by the tag. Or cast the expression when it is the element itself: (<input />) as HTMLInputElement.

ref runs when the element is created, before a parent inserts it, so the element is not in the document yet, as with also: focusing or measuring it inside ref does nothing. The example above focuses the input after document.body.append(form). With @fiorejs/signals, run such code in effect.post, whose first run waits for the next flush, when the element is usually in the document: 

import { effect } from '@fiorejs/signals';

const field = <input ref={(element) => effect.post(() => element.focus())} />;

Event names

Everything after on is the event name as written, except that its first letter is lowercased, so custom events work like built-in ones. Built-in events are lowercase, so onKeydown listens to keydown, but onKeyDown listens to keyDown, which no element fires. An event whose name starts with a capital letter, such as DOMContentLoaded, has no JSX form: listen to it with the builder's on({ DOMContentLoaded }) or in code. 

const widget = (
  <div
    onClick={() => console.log('click')} // listens to click
    onvalueChanged={() => console.log('valueChanged')} // listens to valueChanged
    oncart-add={() => console.log('cart-add')} // listens to cart-add
  />
);
widget.click(); // click

Keys and spread

key is accepted and ignored; key list rows with signal.for(...). Do not spread objects whose keys come from users; see Security.
