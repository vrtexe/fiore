JSX

@fiorejs/jsx lets you write the same elements as JSX. Each JSX expression creates its elements once and returns real DOM nodes, so there is no virtual DOM and no re-rendering.

Setup

Install the runtime next to fiorejs and tell the compiler to import JSX helpers from it: 

npm install fiorejs @fiorejs/jsx

In TypeScript, set the automatic runtime in tsconfig.json. Vite reads the same setting for TypeScript files, so it needs no plugin: 

{
  "compilerOptions": {
    "jsx": "react-jsx",
    "jsxImportSource": "@fiorejs/jsx"
  }
}

What JSX compiles to

The automatic runtime turns each element into a call of jsx, or jsxs when there are several static children, and each fragment into Fragment. All three come from @fiorejs/jsx/jsx-runtime. You can call them yourself, and the result is the same node you would get from the element functions: 

import { jsx, jsxs, Fragment } from '@fiorejs/jsx/jsx-runtime';
import { state } from '@fiorejs/signals';

const count = state(1);

// <p class="note">Clicks: {count}</p>
const note = jsx('p', { class: 'note', children: ['Clicks: ', count] });

// <ul><li>A</li><li>B</li></ul>  (several static children use jsxs)
const list = jsxs('ul', { children: [jsx('li', { children: 'A' }), jsx('li', { children: 'B' })] });

// <>text</>
const fragment = jsx(Fragment, { children: 'text' });

document.body.append(note, list, fragment);

Because the function runs once per expression, a signal in a child or prop is bound at that moment and keeps the spot up to date, exactly as in Binding to the DOM.

Props and attributes

JSX has one list of props, so the runtime decides, per name, whether to set a property or an attribute. The name decides, never the value. Names that start with on are listeners, written in any case, so onclick and onClick both listen to click. value, checked, selected, muted, indeterminate, volume, text and files are properties where the element has them, and camel-case names that the element has a writable property for, such as className or htmlFor, are properties too. Every other name is an attribute, so class, for, aria-label and width="50%" work as in HTML. 

import { computed, state } from '@fiorejs/signals';

const name = state('Ada');
const invalid = computed(() => (name.get() === '' ? 'true' : null));

document.body.append(
  <form onsubmit={(event) => event.preventDefault()}>
    <label for="name">Name</label>
    <input
      id="name"
      class="field"
      value={name}
      aria-invalid={invalid}
      style={{ width: '12rem' }}
      oninput={(event) => name.set(event.currentTarget.value)}
    />
    <img src="/a.png" alt="" title={null} />
    <button type="submit" disabled={false}>
      Save
    </button>
  </form>,
);

title={null} removes the attribute and disabled={false} leaves it out. A style object sets style properties. On SVG elements every prop except listeners and a style object is set as an attribute. Full table: the package README.

Signals in JSX

A signal works as a child or as a prop value, and a derived value is a computed. A bare function is never live: class={() => …} passes the function itself, so write class={computed(() => …)}. A component runs once and returns nodes: 

import { computed, state } from '@fiorejs/signals';

function Counter(props: { start?: number }) {
  const count = state(props.start ?? 0);

  return (
    <div class={computed(() => (count.get() > 5 ? 'many' : 'few'))}>
      <button type="button" onclick={() => count.update((n) => n + 1)}>
        Add one
      </button>
      <span>{count}</span>
    </div>
  );
}

document.body.append(<Counter start={3} />);

The class of the div and the text of the span change with count. Nothing else is created again. For conditions and lists use signal.if(...) and signal.for(...).map(...) inside the markup, since count.get() > 5 ? a : b would be read once.

Fragments and children

<>...</> returns a DocumentFragment, so a component can return several siblings. Children can be nodes, strings, numbers or nested arrays; null, undefined, true and false are skipped. A live child of a fragment keeps updating after the fragment is inserted. 

import { state } from '@fiorejs/signals';

const todos = state([
  { id: 1, text: 'Write docs' },
  { id: 2, text: 'Publish' },
]);

function Term(props: { name: string; text: string }) {
  return (
    <>
      <dt>{props.name}</dt>
      <dd>{props.text}</dd>
    </>
  );
}

document.body.append(
  <dl>
    <Term name="HTML" text="Markup" />
    <Term name="CSS" text="Styles" />
  </dl>,
  <ul>{todos.for((todo) => todo.id).map((todo) => <li>{todo.text}</li>)}</ul>,
);
A JSX expression is typed as Node. Cast it when you need the element type: (<input />) as HTMLInputElement. key is accepted and ignored; key list rows with signal.for(...). Do not spread objects whose keys come from users; see Security.
