Quick start

Derived values

A computed value is a signal whose value is calculated from other signals. It is calculated when something reads it, kept while something depends on it, and recalculated after an input changed.

computed(fn)

computed(fn) returns a read-only signal. Every signal that fn reads with get() becomes an input. It reads like any signal and can be bound to the DOM or read by an effect. 

import { state, computed, effect, flush } from '@fiorejs/signals';

const price = state(10);
const quantity = state(2);
const total = computed(() => price.get() * quantity.get());

effect(() => console.log('total', total.get())); // logs "total 20"

price.set(20);
flush(); // logs "total 40"

When a signal has one input, signal.computed(fn) is shorter. It passes the value of the signal to fn: price.computed((p) => p * 2).

Laziness and caching

A computed does no work until it is read. After the first read it keeps its value while an effect or a binding reads it, and it calculates again on the next read after an input changed. While nothing reads it from an effect or a binding, it does not stay subscribed to its inputs and is recalculated on every read. 

import { state, computed, effect } from '@fiorejs/signals';

const price = state(10);
const total = computed(() => {
  console.log('calculating');
  return price.get() * 2;
});

total.get(); // logs "calculating"
total.get(); // logs "calculating" again: nothing depends on it yet

effect(() => total.get()); // logs "calculating"; from now on the value is kept
total.get();               // cached, logs nothing

A reader of a computed also runs only when the value changed (Object.is). With user.computed((u) => u.name), a binding does not update when another field of user changes, because the name is the same. The same holds for a computed that reads another computed: when the one below it did not change its value, it is not calculated again. 

import { state, computed, effect, flush } from '@fiorejs/signals';

const user = state({ name: 'Ada', visits: 1 });
const name = user.computed((u) => u.name);
const shout = computed(() => {
  console.log('calculating');
  return name.get().toUpperCase();
});

effect(() => console.log(shout.get())); // logs "calculating", then "ADA"

user.set({ name: 'Ada', visits: 2 });
flush(); // name is still 'Ada', so shout is not calculated again and nothing logs

Errors

If fn throws, the computed keeps the error like a value and throws it on every read until an input changes. A reader that catches the error stays subscribed, so it runs again and recovers when the input changes. 

import { state, computed, effect, flush } from '@fiorejs/signals';

const text = state('{"id": 1}');
const parsed = computed(() => JSON.parse(text.get()));

effect(() => {
  try {
    console.log('id', parsed.get().id);
  } catch {
    console.log('invalid JSON');
  }
});

text.set('{');
flush(); // logs "invalid JSON"
text.set('{"id": 2}');
flush(); // logs "id 2"

No writes inside a computed

A computed derives a value, so it must not set signals. Calling set, update or mutate while a computed runs throws, because a write to its own inputs would loop.

To correct a value, derive the corrected one, or correct it where it is set. To react to a change by writing somewhere else, use an effect or an event handler. 

import { state, computed } from '@fiorejs/signals';

const page = state(5);
const last = state(3);

// Wrong: throws "A computed cannot set a signal"
const broken = computed(() => {
  if (page.get() > last.get()) page.set(last.get());
  return page.get();
});

// Right: derive the page that is shown
const shown = computed(() => Math.min(page.get(), last.get()));

try {
  broken.get();
} catch (error) {
  console.log(error.message);
}
console.log(shown.get()); // 3

signal.with

signal.with(fn) calls fn with the signal and returns the result. It adds nothing to the signal. Its use is naming a reusable step, so it reads left to right in a chain. 

import { state } from '@fiorejs/signals';

const todos = state([
  { text: 'Write docs', done: true },
  { text: 'Publish', done: false },
]);

const open = (list) => list.computed((items) => items.filter((item) => !item.done));
const count = (list) => list.computed((items) => items.length);

console.log(todos.with(open).with(count).get()); // 1

Each step returns a signal, so the result is a computed that follows todos. See Signals reference for the exact rules of computed values.
