Events

Listeners go in on. Each key is an event name and each value is a handler, or an object with a handler and the options of addEventListener.

Adding listeners

on(map) maps event names to handlers. fiore calls addEventListener for each entry when the element is created, after the props, attributes and children: 

import { button, input } from 'fiorejs';

const field = input
  .on({ input: (event) => console.log('value:', event.currentTarget.value) })
  .create();

const send = button.on({ click: () => console.log('send') }).create('Send');

document.body.append(field, send);
send.click();
// send

A plain call takes the same map under the on key: button({ on: { click: handler }, children: 'Send' }).

Reaching the element in a handler

Inside a handler, event.currentTarget is the element the listener is attached to. A handler written as a function, not an arrow function, also gets that element as this. event.target can be a descendant, so use currentTarget when you need the element that owns the listener: 

import { button, span } from 'fiorejs';

const inner = span('label');
const toggle = button
  .on({
    click: function (event) {
      console.log(this === event.currentTarget, event.target === inner);
    },
  })
  .create(inner);

document.body.append(toggle);
inner.click();
// true true

Handler objects with options

To pass options such as once, capture, passive or signal, use an object with a handler and an options key. The options go straight to addEventListener: 

import { button } from 'fiorejs';

const once = button
  .on({
    click: {
      handler: () => console.log('first click only'),
      options: { once: true },
    },
  })
  .create('Once');

document.body.append(once);
once.click();
once.click();
// first click only

An object without a handler is ignored.

Removing a listener

fiore has no method to remove a listener. Pass an AbortSignal in the options and abort it when the listener should go. Aborting removes every listener that shares the signal: 

const controller = new AbortController();

const stoppable = button
  .on({ click: { handler: () => console.log('click'), options: { signal: controller.signal } } })
  .create('Stoppable');

controller.abort(); // the listener is gone

Several listeners

Listeners never replace each other. Every on call on a builder adds its map, so you can build up listeners from a template and a particular use. All of them run, in the order they were added: 

import { button } from 'fiorejs';

const tracked = button.on({ click: () => console.log('track') });

const save = tracked
  .on({ click: () => console.log('save') })
  .on({ focus: () => console.log('focused') })
  .create('Save');

document.body.append(save);
save.click();
// track
// save

tracked is unchanged, as with every builder method; see Builders.

Event typing

In TypeScript each element accepts the events of its own event map. A button handler receives a MouseEvent for click, a KeyboardEvent for keydown. In the handler, both this and event.currentTarget are typed as the element, so no cast is needed: 

import { input } from 'fiorejs';

input
  .on({
    input: (event) => console.log(event.currentTarget.value), // HTMLInputElement
    keydown: (event) => console.log(event.key), // KeyboardEvent
  })
  .create();

Some elements take more events: body accepts window events such as popstate, and video accepts media events. Custom event names that contain a hyphen are accepted on every element and typed as CustomEvent. Annotate the parameter to type its detail: 

div.on({
  'cart-add': (event: CustomEvent<{ sku: string }>) => console.log(event.detail.sku),
}).create();

A custom event name without a hyphen must be added to the global event map first: 

declare global {
  interface HTMLElementEventMap {
    itemselected: CustomEvent<{ id: number }>;
  }
}

Delegation

fiore attaches one listener per element you give it. To handle many children with one listener, attach it to the parent and read event.target. This is useful for long lists, and for children that are added later: 

import { li, ul } from 'fiorejs';

const list = ul
  .on({
    click: (event) => {
      const item = event.target.closest('li');
      if (item) console.log('picked', item.textContent);
    },
  })
  .create(['one', 'two', 'three'].map((name) => li(name)));

document.body.append(list);
list.children[1].click();
// picked two

Listeners are the only way to react to events in on. Inline attributes such as onclick are ignored; see Props and attributes. Next: Fragments.
