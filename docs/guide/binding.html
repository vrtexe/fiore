Binding to the DOM

Put a signal where a child, a prop or an attribute goes, and that spot follows the signal. Nothing re-renders and nothing is diffed; each binding is a small effect that updates one place.

Where a signal can go

A signal is a live value. fiorejs binds it to its current value in any of these places:

  • as a child: span(count), or one item of a children array;
  • as a prop: input.props({ value: name });
  • as an attribute: div.attrs({ class: computed(...) }).
import { div, input, span } from 'fiorejs';
import { computed, state, flush } from '@fiorejs/signals';

const name = state('Ada');

const view = div.create([
  input.props({ value: name }).create(),
  span(computed(() => `Hello, ${name.get()}`)),
]);
document.body.append(view);

name.set('Grace');
flush();
console.log(view.querySelector('input').value, view.textContent); // Grace Hello, Grace

A binding runs once when the element is created and again after each change. A live child can return text, a node, a list of nodes or nothing.

Nested props and templates

A value inside a nested prop binds too, so each key of style can follow its own signal. 

import { div } from 'fiorejs';
import { state, flush } from '@fiorejs/signals';

const color = state('tomato');
const size = state('16px');

const box = div.props({ style: { color, fontSize: size } }).create('Styled');
document.body.append(box);

color.set('teal');
flush();
console.log(box.style.color); // teal

Bindings start when the element is created. A builder used as a template, such as const card = div.props({ title }), binds once for every element its create makes.

Bind each key on its own. A computed that returns an object, such as style: computed(() => ({ color })), merges that object into the element on every update and never clears a key that disappears from it.

Classes

classList(entries) builds a class string for className or the class attribute. Strings are always on. The keys of an object are on while their value is truthy; a value can be a boolean, a signal or a getter. 

import { div } from 'fiorejs';
import { classList, state, flush } from '@fiorejs/signals';

const active = state(false);
const enabled = state(true);

const card = div.props({ className: classList(['card', { active, disabled: () => !enabled.get() }]) }).create();
document.body.append(card);

active.set(true);
enabled.set(false);
flush();
console.log(card.className); // card active disabled

Functions are not live

A function is never read as a live value. Wherever it appears in markup it is a callback, as in on({ click: fn }). Write a value derived from signals as computed(() => ...).

The same rule applies to plain reads. open.get() ? a : b in markup is evaluated once, when the element is created, and never switches. Use signal.if for that. In classList, a condition derived from a signal needs a getter or a computed: { disabled: !enabled.get() } is read once.

A computed that builds elements

A computed child can build elements. The bindings and effects it creates belong to that computed. They stop before it recalculates and when nothing reads it any more, the same as inside an effect. 

import { div, p } from 'fiorejs';
import { computed, effect, state, flush } from '@fiorejs/signals';

const show = state(true);
const count = state(0);

const view = computed(() => {
  if (!show.get()) return null;
  effect(() => console.log('count is', count.get()));
  return p(count);
});
document.body.append(div(view)); // logs "count is 0"

count.set(1);
flush();                         // logs "count is 1"
show.set(false);
flush();                         // the computed recalculates; the old effect and binding stop
count.set(2);
flush();                         // logs nothing

The computed builds a new paragraph only when it recalculates, and the bindings of the old one stop then. For a choice between branches, Conditional rendering builds only the branch that is shown and keeps it between changes. For the rest of the rules, see Ownership and cleanup.
