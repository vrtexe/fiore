Styling

fiore does not ship a styling system. You write CSS in your own files and connect it to elements with classes, inline styles and custom properties, each of which can follow a signal.

className and the class attribute

For HTML elements, className in props and class in attrs do the same job. Use the property in HTML. On SVG elements className is a read-only object in the DOM, so set the class attribute there. Both accept a string, and both accept the result of classList: 

import { div } from 'fiorejs';
import { circle, svg } from 'fiorejs/svg';
import { classList, state } from '@fiorejs/signals';

const active = state(false);
const enabled = state(true);

document.body.append(
  div.props({ className: 'card wide' }).create('Property'),
  div.attrs({ class: 'card wide' }).create('Attribute'),
  div.props({ className: classList(['card', { active, disabled: () => !enabled.get() }]) }).create('Live classes'),
  svg.create(circle.attrs({ class: classList({ hot: active }), r: 5 }).create()),
);

active.set(true);

classList takes strings, which are always on, and objects whose keys are on while their value is truthy. A value can be a boolean, a signal or a getter. A condition computed from a signal must be a getter or a computed: { disabled: !enabled.get() } is evaluated once, when the object is created. See classList.

Style objects and live values

The style prop is an object of camel-case style properties. It is merged into the element's style, so a static object sets each property once. A value in the object can be a signal or a computed, and then that property follows it: 

import { div, p } from 'fiorejs';
import { computed, state } from '@fiorejs/signals';

const progress = state(30);
const hue = state(200);

document.body.append(
  div
    .props({
      style: {
        width: computed(() => `${progress.get()}%`),
        backgroundColor: computed(() => `hsl(${hue.get()} 70% 50%)`),
        height: '8px',
      },
    })
    .create(),
  p.props({ style: { color: 'red', fontWeight: 'bold' } }).create('Static style object'),
);

progress.set(80);

Bind each property on its own, as above. A computed that returns a whole style object merges that object on every update and never clears a key that is missing from the next one. Numbers are not converted to pixels, so write `${n}px`, as the width does.

CSS custom properties

A custom property such as --accent cannot be assigned through the style object, because the browser only reads custom properties through style.setProperty(). Put them in the style attribute instead. A computed string makes the attribute live, and also() runs code on the created element for a one-off call: 

import { div } from 'fiorejs';
import { computed, state } from '@fiorejs/signals';

const accent = state('#b8f26d');

document.body.append(
  div.attrs({ class: 'panel', style: computed(() => `--accent: ${accent.get()}; --gap: 12px`) }).create('Themed panel'),
  div.attrs({ style: '--accent: tomato' }).also((element) => element.style.setProperty('--gap', '4px')).create('Static'),
);

accent.set('#6dd5f2');

The live style attribute is replaced as a whole when the signal changes, which is right for a small set of variables. Your stylesheet then uses var(--accent) as usual, so one signal can theme a whole subtree.

Reusable modifiers with with()

with(fn) passes the builder to a function that returns a builder. Such a function is a style modifier: it can be applied to any tag, combined with others, or made conditional. 

import { button, div } from 'fiorejs';

const card = (builder) => builder.props({ className: 'card', style: { padding: '16px' } });
const bordered = (builder) => builder.attrs({ 'data-bordered': '' });
const when = (condition, modifier) => (builder) => (condition ? modifier(builder) : builder);
const isAdmin = true;

document.body.append(
  div.with(card).with(bordered).create('Settings'),
  div.with(card).with(when(isAdmin, (b) => b.attrs({ 'data-admin': '' }))).create('Admin tools'),
  button.with(card).props({ type: 'button' }).create('A button with the same card'),
);

Modifiers apply from left to right and each returns a new builder, so a modifier never changes the builder it was used on. A repeated props call replaces an earlier style object, and a later className replaces an earlier one. Keep one concern per modifier and give modifiers that need to be combined different keys, or merge the styles in a single modifier. For the TypeScript type of a modifier, see TypeScript.

A function in props or attrs is a callback, never a getter. Write a value that depends on a signal as computed(() => …).
