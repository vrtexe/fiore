Builders

A builder collects settings for one tag and creates the element when you call create(). Every method returns a new builder and leaves the old one unchanged, so a builder is also a template you can reuse.

The methods

Each tag function carries the builder methods, so you start a builder from the tag itself. Nothing touches the DOM until create().

MethodTakesRepeated calls
props(map)JavaScript properties of the element, such as className or style.Combine; later keys win.
attrs(map)Attributes, set with setAttribute.Combine; later keys win, and null removes an earlier value.
on(map)Listeners, as { click: fn } or { click: { handler, options } }.Add listeners; they never replace each other.
with(fn)A function that gets the builder and returns a builder.Each call applies its function.
also(fn)A function that gets the created element.Add callbacks, run in order.
create(children)The children, or nothing. Creates the element and returns it.

JSX has no builder methods. A prop on the tag takes the place of props, attrs and on, and JSX decides from the name of the prop which one it is; see Props and attributes and Events. The rest of this page describes the builder.

import { a } from 'fiorejs';

const link = a
  .props({ href: '/docs', className: 'link' })
  .attrs({ rel: 'noopener' })
  .on({ click: () => console.log('followed') })
  .create('Docs');

document.body.append(link);

Immutability and templates

Because each method returns a new builder, a builder you keep never changes. Store a builder once and derive variations from it. The top level of each map is copied when you call the method, so changing the map afterwards has no effect on the builder. 

import { div, h2 } from 'fiorejs';

const card = div.props({ className: 'card' }).on({ click: () => console.log('selected') });

const first = card.create(h2('A'));
const second = card.attrs({ 'aria-label': 'B' }).create(h2('B'));
const third = card.create(h2('C'));

document.body.append(first, second, third);
console.log(first.hasAttribute('aria-label'), third.hasAttribute('aria-label'));
// false false

card.attrs(...) produced a different builder. card itself still has no attributes, so third does not get the label. Nested objects such as style are not copied; they are used as they are when the element is created, so do not change them between calls.

This does not apply in JSX. A JSX expression creates its elements once, where it runs, and is not a template. For a reusable template write a component, a function of props that returns JSX; see Components and state.

Reusable settings with with()

with(fn) calls fn with the builder and uses the builder it returns. Write a modifier once and apply it to any tag, or apply a condition without breaking the chain: 

import { button, div } from 'fiorejs';

const shadow = (b) => b.props({ style: { boxShadow: '0 1px 4px #0003' } });
const admin = (isAdmin) => (b) => (isAdmin ? b.attrs({ 'data-admin': '' }) : b);

const panel = div.with(shadow).with(admin(true)).create('Settings');
const action = button.with(shadow).with(admin(false)).create('Save');

document.body.append(panel, action);

In TypeScript, type a modifier that works on every HTML tag as HTMLModifier, or SVGModifier for SVG. The result keeps the type of the tag it is used on: div.with(card).create() is still an HTMLDivElement.

with does not exist in JSX. Share settings with a component, or spread an object of props into the tag: <div {...shared}>.

The fixed order of application

The order of the calls on a builder does not matter. create() always works in the same sequence:

  1. Create the element.
  2. Assign the props, except value, selectedIndex and checked.
  3. Set the attributes.
  4. Add the children.
  5. Assign value, selectedIndex and checked.
  6. Attach the listeners.
  7. Run the also callbacks.

A listener is therefore never called for a prop set during creation, and a callback sees the finished element.

JSX creates the element the same way: the props, then the attributes and the children, then value, selectedIndex and checked, and the listeners.

Late props

Three props depend on other parts of the element, so fiore assigns them after the attributes and the children. A select can only pick a value that has an option, and a range input clamps its value to min and max, which are attributes: 

import { input, option, select } from 'fiorejs';

const size = select.props({ value: 'M' }).create([option('S'), option('M'), option('L')]);
const range = input.props({ type: 'range', value: '150' }).attrs({ max: '200' }).create();

console.log(size.value, size.selectedIndex);
console.log(range.value);
// M 1
// 150
          
const size = (
  <select value="M">
    <option>S</option>
    <option>M</option>
    <option>L</option>
  </select>
);
const range = <input type="range" value="150" max="200" />;

console.log(size.value, size.selectedIndex);
console.log(range.value);
// M 1
// 150

Without the late assignment, the range would clamp 150 to the default maximum of 100 before the max attribute existed.

Running code on the element with also()

There is no also in JSX. A JSX expression is the element, so keep it in a variable: const surface = <canvas width="100" height="100" />;. It is not in the document yet either.

also(fn) gets the created element after the listeners are attached. The element is not in the document yet, so focusing or measuring does not work there: 

import { canvas } from 'fiorejs';

const surface = canvas
  .props({ width: 100, height: 100 })
  .also((element) => console.log('connected:', element.isConnected))
  .create();

document.body.append(surface);
// connected: false

Use it to keep a reference or to call a method on the new element. For anything that needs the document, wait until the element is appended. Next: Props and attributes.
