Fragments

fragment(children) returns a DocumentFragment that holds the children. Use it when a function must return several nodes and a wrapping element would break the markup.

Creating a fragment

fragment is exported by fiorejs. It takes the same children as a tag: nodes, text, numbers and arrays, with null, undefined and booleans skipped. It returns a native DocumentFragment: 

import { dd, dl, dt, fragment } from 'fiorejs';

const terms = [
  { name: 'Prop', text: 'A property of the element.' },
  { name: 'Attribute', text: 'An attribute in the markup.' },
];

const list = dl(terms.map((term) => fragment([dt(term.name), dd(term.text)])));

document.body.append(list);
console.log(list.children.length);
// 4

fragment calls document.createDocumentFragment(), so it needs a global document, as every tag does. In a test under Node, run it with a DOM such as jsdom.

Each fragment is empty once it is inserted: its children move into the parent, and only they remain. The dl above holds four elements, with no wrapper between them.

When to use it

Use a fragment when you need to return or pass around a group of nodes, and the group has no element of its own. Typical cases:

  • A function that returns a row of cells, a pair such as dt and dd, or several siblings.
  • A parent that only allows certain children, such as tr inside tbody or li inside ul, where an extra div is invalid.
  • A list of nodes you want to insert with one DOM call.
import { fragment, td, tr } from 'fiorejs';

function cells(user) {
  return fragment([td(user.name), td(user.role)]);
}

const row = tr(cells({ name: 'Ada', role: 'Engineer' }));

document.body.append(row);
console.log(row.children.length);
// 2

You do not need a fragment for an array. An array of children is already accepted anywhere a child is, and arrays flatten; see Children. Reach for fragment when the value has to be one node, for example the return value of a component that other code appends.

Inserting a fragment

A fragment can be appended, inserted or used as a child. Its nodes move into the new parent, and the fragment itself is left empty, as with any DocumentFragment. Do not hold on to the fragment to reach its nodes later. Keep references to the nodes, or to the parent: 

import { fragment, li, ul } from 'fiorejs';

const items = fragment([li('one'), li('two')]);
console.log(items.childNodes.length);

const list = ul.create(items);

console.log(items.childNodes.length, list.children.length);
// 2
// 0 2

Live children

A fragment takes live values, such as signals, like any other parent. A live child of a fragment keeps updating after the fragment is inserted. Because a fragment empties when it is inserted, a live child in a fragment always sits between two empty comment nodes, which mark where it lives; they move with its nodes. See Binding to the DOM for how updates work. 

import { fragment, p, strong } from 'fiorejs';
import { state } from '@fiorejs/signals';

const count = state(1);
const note = fragment([strong('Count: '), count]);

const box = p.create(note);
document.body.append(box);
console.log(box.innerHTML);

count.set(2);
await Promise.resolve();
console.log(box.innerHTML);

The signal updates on a microtask, so the second log runs after one await. Outside a fragment, a live child that is the only child of an element needs no comments at all.
