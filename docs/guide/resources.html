Quick start

Async data

A resource loads a value asynchronously and exposes it as a signal, with loading and error as signals of their own. It loads again when its source changes and drops the result of an older load.

resource(source, fetcher)

resource(source, fetcher) calls fetcher with the value of source, a signal or a getter, and loads again whenever the source changes. While the source gives null, undefined or false, nothing is loaded. The fetcher runs untracked, so signals it reads do not become dependencies.

The resource is a signal of the last loaded value. It is undefined until the first load finishes, and it keeps the previous value while it reloads. 

import { effect, resource, state, tick } from '@fiorejs/signals';

const userId = state(1);

const user = resource(userId, (id, { signal }) =>
  new Promise((resolve) => setTimeout(() => resolve({ id, name: `User ${id}` }), 10)),
);

effect(() => console.log(user.loading.get() ? 'loading' : 'idle', user.get()?.name));
// logs "loading undefined" at once

await new Promise((resolve) => setTimeout(resolve, 20)); // logs "idle User 1"
userId.set(2);
await tick(); // logs "loading User 1": the old value stays while loading
await new Promise((resolve) => setTimeout(resolve, 20)); // logs "idle User 2"

With fetch, pass the abort signal along: (id, { signal }) => fetch(`/users/${id}`, { signal }).then((r) => r.json()). resource(fetcher) without a source loads once.

Loading, error, refetch and writes

  • resource.loading is a signal that is true while a load runs.
  • resource.error is a signal of the last error. It is cleared when a new load starts and when the source becomes null, undefined or false.
  • refetch() loads again with the last source value.
  • set(value), update(fn) and mutate(fn) change the value without loading, as on a state, for example for an optimistic change. set also takes undefined, update sets what fn returns, and mutate changes the value in place and notifies. A load that is already running still replaces the changed value when it finishes.

A write is not a load, so it does not cancel one. Here the load for 'b' is running when set is called, and its result replaces the value that was set: 

import { resource, state, tick } from '@fiorejs/signals';

const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
const query = state('a');
const rows = resource(query, async (q) => {
  await sleep(30);
  return `loaded ${q}`;
});
await sleep(50);
query.set('b');
await tick(); // the load for "b" is running
rows.set('optimistic');
console.log(rows.get()); // optimistic
await sleep(60);
console.log(rows.get()); // loaded b

update and mutate work on the loaded value, which is undefined until the first load finishes: 

import { resource, tick } from '@fiorejs/signals';

const todos = resource(async () => [{ text: 'Write docs' }]);
await tick();
await new Promise((resolve) => setTimeout(resolve, 10));

todos.update((list) => [...list, { text: 'Publish' }]);
todos.mutate((list) => list.push({ text: 'Release' })); // in place, readers still run
console.log(todos.get().map((todo) => todo.text)); // [ 'Write docs', 'Publish', 'Release' ]

A failed load that nothing reads error of is also reported with reportError, so it does not go unnoticed. Show the states by binding them: 

import { div } from 'fiorejs';
import { computed, resource, state, flush } from '@fiorejs/signals';

const userId = state(1);
const user = resource(userId, async (id) => {
  if (id === 2) throw new Error('not found');
  return { name: `User ${id}` };
});

const view = div(
  computed(() => (user.error.get() ? 'Could not load' : user.loading.get() ? 'Loading' : user.get()?.name)),
);
document.body.append(view);

await new Promise((resolve) => setTimeout(resolve, 10));
flush();
console.log(view.textContent); // User 1

userId.set(2);
await new Promise((resolve) => setTimeout(resolve, 10));
flush();
console.log(view.textContent); // Could not load

user.set({ name: 'Local' }); // sets the value; error stays until the next load

Setting loading or error yourself is not supported and confuses the resource. Call refetch() only while the resource is in use: on a resource whose effect or list row has gone away it still starts a load.

Aborting and races

The fetcher gets an AbortSignal as { signal }. It aborts when a newer load starts, and when the effect, computed or list row the resource was created in goes away. The result of an older load is ignored even if it arrives later, so a slow first request cannot overwrite a newer answer. 

import { resource, state, tick } from '@fiorejs/signals';

const query = state('a');

const results = resource(query, (text, { signal }) =>
  new Promise((resolve, reject) => {
    const timer = setTimeout(() => resolve(`results for ${text}`), text === 'a' ? 30 : 5);
    signal.addEventListener('abort', () => {
      console.log('aborted', text);
      clearTimeout(timer);
      reject(signal.reason);
    });
  }),
);

query.set('b');
await tick(); // starts the load for "b" and logs "aborted a"
await new Promise((resolve) => setTimeout(resolve, 50));
console.log(results.get()); // results for b

When the aborted fetcher rejects, that error is ignored because the load is no longer the current one. See Ownership and cleanup for how a resource stops with its owner, and Signals reference for the full contract.
