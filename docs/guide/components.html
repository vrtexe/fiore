Components and state

A fiore component is a function that returns an element. It runs once, so there is no render cycle to learn: state lives in signals, and the signals decide which spots of the page change.

Components are functions

A component takes its props as an argument and returns a node. There is nothing to register and no special return type, because every tag function already returns a real DOM element. Children are passed in a prop, and any node, string or array of these is accepted, as in Children. 

import { article, h2, li, ul } from 'fiorejs';

function Tags(props) {
  return ul(props.items.map((item) => li(item)));
}

function Card(props) {
  return article.props({ className: 'card' }).create([h2(props.title), props.children]);
}

document.body.append(Card({ title: 'Release notes', children: Tags({ items: ['Fixes', 'Docs'] }) }));

The function body runs one time per call. It does not run again when data changes, so a value read in the body, such as props.items above, is read once. The next sections show how to keep a page current without running the function again.

Local state

Create a signal inside the component and each call gets its own. Bind the signal where it is shown and write to it from a listener. Only the bound text changes when the value does. 

import { button, div, span } from 'fiorejs';
import { state } from '@fiorejs/signals';

function Counter(props) {
  const count = state(props.start ?? 0);

  return div.create([
    button.on({ click: () => count.update((n) => n - 1) }).create('-'),
    span(count),
    button.on({ click: () => count.update((n) => n + 1) }).create('+'),
  ]);
}

document.body.append(Counter({ start: 5 }), Counter({}));

The two counters do not affect each other, because each call of Counter created its own count. The update reaches the page on a microtask after the click handler returns; see Timing and batching.

Shared state in modules

A signal created at the top level of a module belongs to everyone who imports the module, because a module is evaluated once. This is the whole mechanism for shared state: export the signals and the functions that change them, and import them where needed. There is no provider or context. 

import { button, header, span } from 'fiorejs';
import { computed, state } from '@fiorejs/signals';

// cart.js: a module is evaluated once, so everything that imports it shares these signals
const items = state([]);
const total = computed(() => items.get().reduce((sum, item) => sum + item.price, 0));
const add = (item) => items.update((list) => [...list, item]);

// header.js
const CartBadge = () => span(computed(() => `${items.get().length} items, ${total.get()} CHF`));

// product.js
const Buy = () => button.on({ click: () => add({ name: 'Mug', price: 12 }) }).create('Buy a mug');

document.body.append(header(CartBadge()), Buy());

The example puts three files in one so that it runs as it stands. In a real project the store, the badge and the button are three modules, and the badge updates when the button adds an item.

Passing signals down

Pass the signal, not its current value. A value read with get() in the parent is a snapshot, and the child never hears about later changes. A child that should accept both fixed and changing values reads its prop with read(), which returns the value of a signal or a plain value unchanged. 

import { div, p } from 'fiorejs';
import { computed, read, state } from '@fiorejs/signals';

function Price(props) {
  const label = computed(() => `${read(props.amount).toFixed(2)} CHF`);
  return p(label);
}

function Order(props) {
  return div.create([Price({ amount: props.net }), Price({ amount: computed(() => props.net.get() * 1.081) }), Price({ amount: 5 })]);
}

const net = state(100);
document.body.append(Order({ net }));
net.set(200);

All three Price calls work with the same code: a signal, a derived value and a plain number. In TypeScript the prop is typed Reactive<number>; see TypeScript. read() inside computed subscribes the result to the signal, which is why the label follows net.

Lists of components

signal.for(key).map(render) calls a component once per item and reuses the rows of items it has seen, so a change to the list does not rebuild the rest. A row is rendered once, for the item it was created with. Fields that change over time therefore belong in signals inside the item. 

import { button, li, ul } from 'fiorejs';
import { state } from '@fiorejs/signals';

const todos = state([
  { id: 1, text: 'Write docs', done: state(false) },
  { id: 2, text: 'Publish', done: state(false) },
]);

function Todo(todo) {
  return li
    .props({ className: todo.done.computed((done) => (done ? 'done' : '')) })
    .on({ click: () => todo.done.update((done) => !done) })
    .create([todo.text, button.on({ click: () => todos.update((list) => list.filter((t) => t !== todo)) }).create('Remove')]);
}

document.body.append(ul(todos.for((todo) => todo.id).map(Todo)));

Replace the array to change the list: todos.update((list) => list.filter(…)) removes a row, and the other rows stay as they are. Pushing into the array does not notify; see Arrays and objects and Lists.

Cleanup

Bindings stop on their own when the content they belong to is replaced: a list row that is dropped, a branch of if that is switched off, or a computed child that recalculates. An element that is removed from the document pauses its bindings and resumes them when it is inserted again.

For work outside the DOM, such as a timer or a subscription, use an effect and return a function from it. That function runs before the next run and when the effect stops. root() gives you the stop switch for a whole tree: 

import { div } from 'fiorejs';
import { effect, root, state } from '@fiorejs/signals';

const now = state(Date.now());

function Clock() {
  effect(() => {
    const timer = setInterval(() => now.set(Date.now()), 1000);
    return () => clearInterval(timer);
  });
  return div(now.computed((time) => new Date(time).toISOString()));
}

const dispose = root(() => document.body.append(Clock()));

// later: stops the effect, which clears the timer, and every binding of Clock
dispose();
Calling the function returned by root() stops the bindings for good, also if the element is inserted again later. See Ownership and cleanup and the cleanup reference.
