Children

Children are what goes inside an element. You pass them to a tag, to create(), or under the children key of a data object, and all three accept the same values.

Accepted children

A tag takes one argument, so a single child needs no array and several children go in one. The element receives them in order.

A child is one of these:

  • a DOM node, such as an element, a text node or a fragment;
  • a string, a number or a bigint, which becomes a text node;
  • an array of children, nested as deep as you like;
  • null, undefined, true or false, which are skipped;
  • a live value, such as a signal, which keeps its place up to date; see Signals.
import { li, p, strong, ul } from 'fiorejs';

const list = ul([
  li('Text'),
  li(42),
  li(10n),
  li(strong('A node')),
]);

document.body.append(p(['Total: ', 3, ' items']), list);

Three ways to pass children

A plain call, a data object and a builder take the same children and produce the same element: 

import { em, p } from 'fiorejs';

const a = p(['Hi ', em('there')]);
const b = p({ children: ['Hi ', em('there')] });
const c = p.create(['Hi ', em('there')]);

console.log(a.outerHTML === b.outerHTML, b.outerHTML === c.outerHTML);
// true true

Prefer create() after a builder, and the plain call for static content. When the value comes from outside your code, use create(value), because a plain object passed to a plain call would be read as a data object.

Nesting arrays

Arrays are flattened, so the result of map can sit next to other children without any joining. A cyclic array is read once and then skipped. 

import { li, ul } from 'fiorejs';

const names = ['Ada', 'Grace', 'Edsger'];

const list = ul([
  names.map((name) => li(name)),
  [[li('and others')]],
]);

document.body.append(list);
console.log(list.children.length);
// 4

Skipped values

null, undefined, true and false add nothing. That makes a condition a plain expression: 

import { div, span } from 'fiorejs';

function badge(user) {
  return div([
    span(user.name),
    user.isAdmin && span.props({ className: 'badge' }).create('admin'),
    user.nickname ?? null,
  ]);
}

document.body.append(
  badge({ name: 'Ada', isAdmin: true, nickname: 'countess' }),
  badge({ name: 'Bob', isAdmin: false }),
);

0 and the empty string are not skipped. 0 shows as the text 0, so count && node prints 0 when the count is zero. Write count > 0 && node instead.

Text and nodes

A string child becomes a text node, never markup. p('<b>hi</b>') shows the characters <b>hi</b>. There is no HTML parsing in children, so untrusted text is safe there. To create a bold word, use a node: strong('hi').

An object that is not a node is shown as text through String(value), and a plain object passed to a tag call is read as the data object, as Elements and tags explains. 

import { p, strong } from 'fiorejs';

const safe = p('<img src=x onerror=alert(1)>');
const bold = p(['Press ', strong('Save')]);

console.log(safe.children.length, safe.textContent);
console.log(bold.children.length, bold.textContent);
// 0 <img src=x onerror=alert(1)>
// 1 Press Save

Children and props that set content

Props such as textContent and innerHTML also put content in an element. Props are assigned before the children. When there is at least one child that is not skipped, the first one replaces whatever the prop wrote. With no children, the content of the prop stays. 

import { div } from 'fiorejs';

const kept = div.props({ textContent: 'from the prop' }).create();
const replaced = div.props({ textContent: 'from the prop' }).create('from the child');
const skipped = div.props({ textContent: 'from the prop' }).create([null, false]);

console.log(kept.textContent);
console.log(replaced.textContent);
console.log(skipped.textContent);
// from the prop
// from the child
// from the prop

Do not set innerHTML from untrusted data. Use children for text, and props for markup only when you wrote it. Next: Events.
