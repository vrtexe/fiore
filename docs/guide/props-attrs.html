Props and attributes

props sets JavaScript properties on the element, and attrs sets HTML attributes. They are separate on purpose, so you always know which one you changed.

Properties and attributes

A property lives on the JavaScript object: input.value, element.className, checkbox.checked. An attribute lives in the markup: value="...", class="...", checked. They often mirror each other, but not always. The value attribute of an input is only its default, while the value property is what the user sees.

JSX has no separate props and attrs. JSX decides by the name of the prop, as the table at the end of this page shows. className and htmlFor are properties; class, for and aria-describedby are attributes.

props assigns with element[name] = value. attrs calls setAttribute(name, value). The names follow the platform: props use className and htmlFor, attributes use class and for. 

import { input, label } from 'fiorejs';

const email = input
  .props({ id: 'email', type: 'email', value: 'ada@example.com' })
  .attrs({ placeholder: 'you@example.com', 'aria-describedby': 'email-help' })
  .create();

const caption = label.props({ htmlFor: 'email' }).create('Email');

document.body.append(caption, email);
console.log(email.value, email.getAttribute('value'));
// ada@example.com null
          
const email = (
  <input
    id="email"
    type="email"
    value="ada@example.com"
    placeholder="you@example.com"
    aria-describedby="email-help"
  />
);

const caption = <label htmlFor="email">Email</label>;

document.body.append(caption, email);
console.log(email.value, email.getAttribute('value'));
// ada@example.com null

The prop value changed what the field shows, but no value attribute was written. In JSX too, value is a property.

Nested props

Some properties hold an object, such as style and dataset. Pass a plain object and fiore merges it into the existing one instead of replacing it. That is the same as assigning each key on element.style:

style takes an object, and each key is set on element.style. dataset is read-only, so write each key as a data-* attribute instead:

import { div } from 'fiorejs';

const box = div
  .props({
    className: 'box',
    style: { color: 'tomato', paddingBlock: '8px' },
    dataset: { id: '42', kind: 'demo' },
  })
  .create('Styled');

document.body.append(box);
console.log(box.dataset.id, box.style.color);
// 42 tomato
          
const box = (
  <div className="box" style={{ color: 'tomato', paddingBlock: '8px' }} data-id="42" data-kind="demo">
    Styled
  </div>
);

document.body.append(box);
console.log(box.dataset.id, box.style.color);
// 42 tomato

On one builder, a later props call replaces an earlier value of the same top-level key, so a second style object replaces the first. A nested object is merged into the element after the other keys of its map.

Attribute rules

An attribute value is converted to a string by setAttribute. Three rules decide whether an attribute is written at all. They are the same for the builder and for JSX:

  • null, undefined and false leave the attribute out, or remove it if an earlier call set it.
  • Every other value is written, including 0 and the empty string. true becomes the string "true".
  • aria-* and data-* attributes, and the enumerated attributes contenteditable, draggable and spellcheck, keep false as the string "false", because that value has a meaning.
import { button } from 'fiorejs';

const toggle = button
  .attrs({
    'aria-pressed': false,
    'data-count': 0,
    disabled: false,
    hidden: null,
    title: '',
    spellcheck: false,
  })
  .create('Mute');

document.body.append(toggle);
          
const toggle = (
  <button aria-pressed={false} data-count={0} disabled={false} hidden={null} title="" spellcheck={false}>
    Mute
  </button>
);

document.body.append(toggle);

The result is aria-pressed="false", data-count="0", title="" and spellcheck="false". There is no disabled and no hidden. Merging two attrs calls works the same way: 

import { a } from 'fiorejs';

const base = a.attrs({ target: '_blank', rel: 'noopener' });
const same = base.attrs({ target: null }).create('Same tab');

console.log(same.outerHTML);
// <a rel="noopener">Same tab</a>
          
const base = { target: '_blank', rel: 'noopener' };
const same = (
  <a {...base} target={null}>
    Same tab
  </a>
);

console.log(same.outerHTML);
// <a rel="noopener">Same tab</a>
Values are not checked. A javascript: URL in href or src runs when it is followed. Check the scheme of a URL that comes from untrusted data, and never take attribute names from it.

Inline handler attributes are ignored

An attribute whose name is on followed by letters only, such as onclick or onunload, in any case, is never set. Browsers run the text of such attributes as script, so fiore skips them. A hyphenated name such as on-tap is set. Listeners belong in on; see Events.

In JSX every prop that starts with on is a listener, so onclick takes a function and is never an attribute. The text of an inline handler cannot be written as a prop.

import { button } from 'fiorejs';

const bad = button.attrs({ onclick: 'alert(1)', 'on-tap': 'open' }).create('Press');

console.log(bad.outerHTML);
// <button on-tap="open">Press</button>

When to use which

JSX decides by the name of the prop, never by the value:

PropApplied as
on and an event name, in any case: onclick, onClickAn event listener, for click.
null, as in title={null}Removes the attribute.
style with an objectStyle properties.
A camel-case name the element has a writable property for: className, textContent, htmlForA property.
value, checked, selected, muted, indeterminate, volume, text, files, where the element has itA property.
Any other name: class, for, id, type, disabled, aria-label, widthAn attribute.

Because only the name counts, width="50%" stays an attribute and disabled={false} removes the attribute. On SVG elements every prop except listeners and a style object is an attribute. On a custom element, an object or a function goes to the property of that name.

  • Use props for state the element holds: value, checked, disabled, className, textContent, style.
  • Use attrs for names that have no property, such as aria-*, data-*, role and list, and for the geometry and presentation attributes of SVG elements, which are read-only objects as properties.
  • Use attrs when the markup itself must carry the value, for example a default that a form reset restores.
  • A prop with the value undefined leaves the element's property unchanged. Use an attribute with null to remove something.
