Quick start

TypeScript

Every package ships declarations, and the types follow the tag. A tag function returns the exact element type, and checks props, attributes and listeners against that element. No extra setup is needed.

Element types per tag

In JSX, tags, attributes, properties and listeners are checked against the element: maxLength is a number on an input, and href is rejected on one. In a listener, event.currentTarget is the element, so event.currentTarget.value needs no cast. A JSX expression itself is typed as Node, not as the element, so use ref, which is typed by the tag, or cast it with as when you need the element type.

input returns HTMLInputElement, div returns HTMLDivElement, and the same holds for SVG and MathML tags, so you can use the created element without a cast. In props, the keys and value types come from the element: maxLength is a number on an input, and href is rejected on one. In on, the event type comes from the element's event map and event.currentTarget is the element. 

import { button, div, input, type HTMLModifier } from 'fiorejs';

const field = input
  .props({ type: 'text', value: 'Ada', maxLength: 40 })
  .attrs({ 'aria-label': 'Name', autocomplete: 'name' })
  .on({ input: (event) => console.log(event.currentTarget.value) })
  .create();
field satisfies HTMLInputElement;

const box = div('Hello');
box satisfies HTMLDivElement;

const rounded: HTMLModifier = (builder) => builder.props({ className: 'rounded' });

div.with(rounded).create(); // HTMLDivElement
button.with(rounded).props({ type: 'submit' }).create('Save'); // HTMLButtonElement
let field!: HTMLInputElement;
<input
  type="text"
  value="Ada"
  maxLength={40}
  aria-label="Name"
  autocomplete="name"
  oninput={(event) => console.log(event.currentTarget.value)}
  ref={(element) => (field = element)} // element is an HTMLInputElement
/>;
field satisfies HTMLInputElement;

const box = <div>Hello</div>; // typed as Node, so cast it or use ref for the element type
(box as HTMLDivElement) satisfies HTMLDivElement;

Typed props, attributes and listeners

JSX props take the writable properties of the element and its attributes, including aria-* and data-*. A prop the element does not have is a type error, which catches a misspelled property early. A listener is written on and the event name, or with a capital first letter, so the types offer onkeydown and onKeydown. Custom events whose name has a hyphen, such as oncart-add, are accepted on every element and typed as CustomEvent; annotate the parameter to type its detail. A custom event name without a hyphen needs an entry in the global event map. Tags with a hyphen are custom elements and accept any prop.

props takes the writable properties of the element, and attrs takes its attributes, including aria-* and data-*. A prop the element does not have is a type error, which catches a misspelled property early. Custom events whose name has a hyphen are accepted on every element and typed as CustomEvent; annotate the parameter to type its detail. A custom event name without a hyphen needs an entry in the global event map. dataset is a typed prop, whose keys are merged into the element's data-* attributes, and element('user-card'), with a hyphenated name, returns the tag of a custom element, which takes any attribute: 

import { div, input, video } from 'fiorejs';
import { circle, type SVGModifier } from 'fiorejs/svg';

const hot: SVGModifier = (builder) => builder.attrs({ fill: 'tomato' });
circle.with(hot).attrs({ r: '5' }).create(); // SVGCircleElement

div.on({ 'cart-add': (event: CustomEvent<{ sku: string }>) => console.log(event.detail.sku) }).create();

video.on({ ended: function () { this.currentTime = 0; } }).create();

declare global {
  interface HTMLElementEventMap {
    itemselected: CustomEvent<{ id: number }>;
  }
}

div.on({ itemselected: (event) => console.log(event.detail.id) }).create();

// @ts-expect-error an input has no `href` property
input.props({ href: '/x' }).create();
// @ts-expect-error a div has no `value` property
div.props({ value: 'x' }).create();
<div oncart-add={(event: CustomEvent<{ sku: string }>) => console.log(event.detail.sku)} />;

<video onended={(event) => (event.currentTarget.currentTime = 0)} />;

declare global {
  interface HTMLElementEventMap {
    itemselected: CustomEvent<{ id: number }>;
  }
}

<div onitemselected={(event) => console.log(event.detail.id)} />;

// @ts-expect-error an input has no `href` property
<input href="/x" />;
// @ts-expect-error a div has no `value` property
<div value="x" />;

HTMLModifier and SVGModifier

There is no with in JSX, so there is no modifier type. A reusable piece is a component, a function from a typed props object to a node, as the next section shows.

A function passed to with that should work on every tag has the type HTMLModifier, or SVGModifier for SVG. The builder keeps the type of the tag it is used on, so div.with(rounded).create() is still an HTMLDivElement (the first snippet above shows it). For a modifier that only suits one tag, type the parameter as that tag's builder instead. HTMLModifier comes from fiorejs and SVGModifier from fiorejs/svg.

Typing signals and components

state<T>() returns State<T>, and computed returns Computed<T>. Give state a type argument when the initial value is narrower than the type, as with null below. A component is a function that takes a typed props object and returns a node, or any other child, and its props are checked where it is used as a tag. Use Reactive<T>, a plain value or a signal of it, for props that may change, and unwrap them with read(). For children, use the Child type from @fiorejs/jsx. The item in map keeps the type of the array, and in a keyed list, after for, it is a Signal of that type.

state<T>() returns State<T>, and computed returns Computed<T>. Give state a type argument when the initial value is narrower than the type, as with null below. A component is a typed function. Use Reactive<T>, a plain value or a signal of it, for props that may change, and unwrap them with read(). The item in map keeps the type of the array, and in a keyed list, after for, it is a Signal of that type. 

import { div, span } from 'fiorejs';
import { computed, read, state, type Computed, type Reactive, type State } from '@fiorejs/signals';

type User = { id: number; name: string };

const user: State<User | null> = state<User | null>(null);
const label: Computed<string> = computed(() => user.get()?.name ?? 'Guest');

function Greeting(props: { name: Reactive<string>; excited?: boolean }): HTMLDivElement {
  return div(span(computed(() => `Hello, ${read(props.name)}${props.excited ? '!' : ''}`)));
}

Greeting({ name: 'Ada' });
Greeting({ name: label, excited: true });

const users = state<User[]>([{ id: 1, name: 'Ada' }]);
div(users.for((item) => item.id).map((item) => span(item.computed((user) => user.name)))); // item is Signal<User>
import { computed, read, state, type Computed, type Reactive, type State } from '@fiorejs/signals';

type User = { id: number; name: string };

const user: State<User | null> = state<User | null>(null);
const label: Computed<string> = computed(() => user.get()?.name ?? 'Guest');

function Greeting(props: { name: Reactive<string>; excited?: boolean }) {
  return (
    <div>
      <span>{computed(() => `Hello, ${read(props.name)}${props.excited ? '!' : ''}`)}</span>
    </div>
  );
}

<Greeting name="Ada" />;
<Greeting name={label} excited />;

const users = state<User[]>([{ id: 1, name: 'Ada' }]);
<div>{users.for((item) => item.id).map((item) => <span>{item.computed((user) => user.name)}</span>)}</div>; // item is Signal<User>

A component that forwards its props to an element takes the element's props type, JSX.IntrinsicElements['input']. JSX is exported from @fiorejs/jsx, so import it as a type from there. The wrapper then accepts every prop and listener of input, with the same types as a plain <input>. 

import type { JSX } from '@fiorejs/jsx';

export function TextInput(props: JSX.IntrinsicElements['input']) {
  return <input {...props} />;
}

document.body.append(<TextInput type="email" oninput={(event) => console.log(event.currentTarget.value)} />);

Signals fit the Live<T> type of fiorejs, so a signal is accepted wherever a value of that type is. The full list of signal types is in the Signals reference.

The type subpaths

The main types are exported from the entry points: fiorejs exports HTMLModifier, HTMLBuilder, Children, Live, LiveValue and BindContext, and fiorejs/svg exports SVGModifier. Children, the type of what a tag takes as children, is exported from fiorejs/svg and fiorejs/math too, for components that pass their children on. The rest live in the declaration files under lib/types, which the fiorejs/type/* subpath maps to. Use it for types such as ElementData and HTMLTag: 

import type { Live, LiveValue, HTMLBuilder } from 'fiorejs';
import type { ElementData, HTMLTag } from 'fiorejs/type/html.dom.d.ts';
import type { Signal } from '@fiorejs/signals';

type Props = { title: Live<string> };

const asBuilder = (builder: HTMLBuilder): HTMLBuilder => builder;
declare const tag: HTMLTag<'section'>;
declare const data: ElementData<'section'>;
declare const live: LiveValue<number>;
declare const signal: Signal<number>;
const fromSignal: LiveValue<number> = signal;
export { asBuilder, tag, data, live, fromSignal };
export type { Props };
The entry points are listed in the API reference and the types in TypeScript types. A project must resolve fiorejs once: two copies of the declarations make the LIVE symbol type differ, and TypeScript then rejects a signal as a live value. Use moduleResolution node16, nodenext or bundler so the exports field is read.
