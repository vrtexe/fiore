Quick start

Forms

Form controls keep their own state in the browser. In fiore you set that state through props, listen to input or change events, and keep a signal in step with the control.

Value and checked are props

value and checked are JavaScript properties, so they go in props, not in attrs. The attribute only sets the initial state of a control, while the property is the state the user sees. A plain value sets the control once. A signal keeps it current: when the signal changes, the control changes.

value and checked are JavaScript properties, and JSX sets them as properties, so write them as props like any other: <input value={name} />. A signal keeps it current: when the signal changes, the control changes. Listeners are props that start with on, such as oninput and onchange, and onInput works too.

fiore assigns value, selectedIndex and checked last, after the other props, the attributes and the children. That order matters for controls whose value depends on their content, and it is the same whatever order you call props, attrs and create in.

Two-way binding with signals

There is no special two-way syntax. Bind the signal to the property and write the signal from the event. A text input uses input, which fires on every keystroke: 

import { input, label, p } from 'fiorejs';
import { state } from '@fiorejs/signals';

const name = state('Ada');

document.body.append(
  label(['Name ', input.props({ type: 'text', value: name }).on({ input: (event) => name.set(event.currentTarget.value) }).create()]),
  p(['Hello, ', name]),
);
import { state } from '@fiorejs/signals';

const name = state('Ada');

document.body.append(
  <label>
    Name <input type="text" value={name} oninput={(event) => name.set(event.currentTarget.value)} />
  </label>,
  <p>Hello, {name}</p>,
);

The signal drives the control, and the control drives the signal. The paragraph reads the same signal, so it shows what the user types. Setting name from anywhere else, such as a reset button, also updates the input.

The control is written only when the signal changes. Setting a signal to the value it already has does nothing, so a handler that corrects the input, such as a clamp, a rounding or a rejected character, or a reset to the current value, leaves the control showing what the user typed. Below, typing 15 while amount is already 1 keeps 15 in the field; typing it while amount is 0.5 shows 1. Write the control in the handler as well: 

const amount = state(1);

input
  .props({ type: 'number', value: amount.computed(String) })
  .on({
    input: (event) => {
      const next = Math.min(1, event.currentTarget.valueAsNumber);
      amount.set(next);
      event.currentTarget.value = String(next); // amount may already be 1, then set does not write the field
    },
  })
  .create();
const amount = state(1);

<input
  type="number"
  value={amount.computed(String)}
  oninput={(event) => {
    const next = Math.min(1, event.currentTarget.valueAsNumber);
    amount.set(next);
    event.currentTarget.value = String(next); // amount may already be 1, then set does not write the field
  }}
/>;

A checkbox uses checked and the change event, and reads event.currentTarget.checked: 

import { input, label, p } from 'fiorejs';
import { state } from '@fiorejs/signals';

const agreed = state(false);

document.body.append(
  label([
    input.props({ type: 'checkbox', checked: agreed }).on({ change: (event) => agreed.set(event.currentTarget.checked) }).create(),
    ' I agree',
  ]),
  p(agreed.if(() => 'Agreed').else(() => 'Not agreed')),
);
import { state } from '@fiorejs/signals';

const agreed = state(false);

document.body.append(
  <label>
    <input type="checkbox" checked={agreed} onchange={(event) => agreed.set(event.currentTarget.checked)} /> I agree
  </label>,
  <p>{agreed.if(() => 'Agreed').else(() => 'Not agreed')}</p>,
);

currentTarget is the element the listener was added to, typed as that element in TypeScript, so no cast is needed. The value of a type="number" input is still a string; read valueAsNumber when you need the number.

Select and the late props order

A select chooses its option by value, so the options have to exist when the value is applied. Because fiore assigns value after the children, you can write the prop before the options and still get the right selection: 

import { option, select } from 'fiorejs';
import { state } from '@fiorejs/signals';

const size = state('m');
const sizes = { s: 'Small', m: 'Medium', l: 'Large' };

document.body.append(
  select
    .props({ value: size })
    .on({ change: (event) => size.set(event.currentTarget.value) })
    .create(Object.entries(sizes).map(([value, text]) => option.props({ value }).create(text))),
);
import { state } from '@fiorejs/signals';

const size = state('m');
const sizes = { s: 'Small', m: 'Medium', l: 'Large' };

document.body.append(
  <select value={size} onchange={(event) => size.set(event.currentTarget.value)}>
    {Object.entries(sizes).map(([value, text]) => (
      <option value={value}>{text}</option>
    ))}
  </select>,
);

The select shows Medium, because size holds 'm' and the options were created first. With the DOM alone the order would be your job. The same rule applies to selectedIndex, and to a range input whose max attribute must be set before its value is clamped. See Props and attributes.

The options may also arrive later, for example after a load. A select with a value prop assigns its value again when options are added or replaced, so it selects the option that matches even though it was empty when the value was first applied. Without this, the browser would select the first option and the select and the signal would disagree. The select is corrected in a microtask, when the browser reports the new options: 

import { option, select } from 'fiorejs';
import { flush, state } from '@fiorejs/signals';

const choice = state('b');
const options = state([]);

const sel = select
  .props({ value: choice })
  .on({ change: (event) => choice.set(event.currentTarget.value) })
  .create(options.map((o) => option.props({ value: o }).create(o)));
document.body.append(sel);

options.set(['a', 'b', 'c']);
flush();
await new Promise((resolve) => setTimeout(resolve)); // the select sees the new options
console.log(sel.value); // b
choice.set('c');
flush();
console.log(sel.value); // c
import { flush, state } from '@fiorejs/signals';

const choice = state('b');
const options = state([]);

const sel = (
  <select value={choice} onchange={(event) => choice.set(event.currentTarget.value)}>
    {options.map((o) => (
      <option value={o}>{o}</option>
    ))}
  </select>
);
document.body.append(sel);

options.set(['a', 'b', 'c']);
flush();
await new Promise((resolve) => setTimeout(resolve)); // the select sees the new options
console.log(sel.value); // b
choice.set('c');
flush();
console.log(sel.value); // c

The select shows b after the options load, and c after choice is set to 'c'.

Binding selected on each option. Before fiore 2.2 a select with late options had to bind selected on every option instead of value on the select. That still works, but it is no longer needed.

Showing validation

Derive the error from the value with computed and show it when the field has been touched. Both are signals, so the message appears and disappears without any extra code. The form below also covers the submit handler: 

import { button, form, input, label, p } from 'fiorejs';
import { computed, state } from '@fiorejs/signals';

const email = state('');
const touched = state(false);
const error = computed(() => (/^\S+@\S+\.\S+$/.test(email.get()) ? '' : 'Enter an email address'));
const sent = state([]);

const submit = (event) => {
  event.preventDefault();
  touched.set(true);
  if (error.get()) return;
  sent.update((list) => [...list, email.get()]);
  email.set('');
  touched.set(false);
};

document.body.append(
  form.on({ submit }).attrs({ novalidate: '' }).create([
    label([
      'Email ',
      input
        .props({ type: 'email', value: email })
        .attrs({ 'aria-invalid': computed(() => (touched.get() && error.get() ? 'true' : null)) })
        .on({ input: (event) => email.set(event.currentTarget.value), blur: () => touched.set(true) })
        .create(),
    ]),
    p.attrs({ role: 'alert' }).create(touched.computed((shown) => (shown ? error.get() : ''))),
    button.props({ type: 'submit' }).create('Subscribe'),
  ]),
);
import { computed, state } from '@fiorejs/signals';

const email = state('');
const touched = state(false);
const error = computed(() => (/^\S+@\S+\.\S+$/.test(email.get()) ? '' : 'Enter an email address'));
const sent = state([]);

const submit = (event) => {
  event.preventDefault();
  touched.set(true);
  if (error.get()) return;
  sent.update((list) => [...list, email.get()]);
  email.set('');
  touched.set(false);
};

document.body.append(
  <form onsubmit={submit} novalidate="">
    <label>
      Email{' '}
      <input
        type="email"
        value={email}
        aria-invalid={computed(() => (touched.get() && error.get() ? 'true' : null))}
        oninput={(event) => email.set(event.currentTarget.value)}
        onblur={() => touched.set(true)}
      />
    </label>
    <p role="alert">{touched.computed((shown) => (shown ? error.get() : ''))}</p>
    <button type="submit">Subscribe</button>
  </form>,
);

touched turns on at blur or at a submit attempt, so an empty field is not marked invalid before the user has been there. aria-invalid is bound as an attribute: a signal holding null removes the attribute, and the paragraph with role="alert" announces the message. The novalidate attribute turns off the browser's own bubbles so that this message is the only one.

Submitting

Listen to submit on the form, not to click on the button, so that pressing Enter in a field works too. Call event.preventDefault() to stay on the page. FormData reads every named control at once, which is handy when the form is not bound to signals: 

import { button, form, input, output } from 'fiorejs';
import { state } from '@fiorejs/signals';

const result = state('Nothing sent yet');

document.body.append(
  form
    .on({
      submit: (event) => {
        event.preventDefault();
        const data = Object.fromEntries(new FormData(event.currentTarget));
        result.set(`Sent ${JSON.stringify(data)}`);
      },
    })
    .create([
      input.props({ name: 'title', value: 'Draft' }).create(),
      input.props({ name: 'qty', type: 'number', value: '2' }).create(),
      button.props({ type: 'submit' }).create('Send'),
      output(result),
    ]),
);
import { state } from '@fiorejs/signals';

const result = state('Nothing sent yet');

document.body.append(
  <form
    onsubmit={(event) => {
      event.preventDefault();
      const data = Object.fromEntries(new FormData(event.currentTarget));
      result.set(`Sent ${JSON.stringify(data)}`);
    }}
  >
    <input name="title" value="Draft" />
    <input name="qty" type="number" value="2" />
    <button type="submit">Send</button>
    <output>{result}</output>
  </form>,
);
Everything read from a form is user input. Show it as a child, {value} or a signal, and never spread an object built from it into a tag or pass it to innerHTML. See Security.
