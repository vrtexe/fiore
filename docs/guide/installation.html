Installation

Install fiorejs from npm and import the tags you need. It is plain ES modules with TypeScript declarations and no runtime dependencies, so it also runs in a browser without a build step.

Install with npm

npm install fiorejs

Add @fiorejs/signals if the page has state that changes, and @fiorejs/jsx if you want JSX that returns real DOM nodes: 

npm install fiorejs @fiorejs/signals @fiorejs/jsx

JSX also needs the compiler to use the runtime of @fiorejs/jsx. In tsconfig.json set the import source; JSX lists the settings of other tools:

{
  "compilerOptions": {
    "jsx": "react-jsx",
    "jsxImportSource": "@fiorejs/jsx"
  }
}

fiorejs creates elements with the global document, so it runs in a browser or in a DOM environment such as jsdom. Versions up to 1.1.2 were published as html-dom-js; version 2 changed the API, and the notes are in the upgrade section of the README.

To start from a working project instead, use npm create @fiorejs.

Entry points

The package has several entry points, so a module only imports the namespace it needs.

ImportWhat it exports
fiorejsOne function per HTML tag, element, fragment, LIVE, and a default export with every HTML tag as an object. The same as fiorejs/html.
fiorejs/htmlThe same as fiorejs.
fiorejs/svgOne function per SVG tag and the SVG element. The default export is an object of the tags.
fiorejs/mathOne function per MathML tag and the MathML element. The default export is an object of the tags.
fiorejs/html/deprecatedTags of obsolete HTML elements, such as center and marquee, each marked deprecated.
fiorejs/globalThe default exports of the other modules as named exports: html, svg and math, and deprecatedHtml.
fiorejs/type/*The type declaration files in lib/types. The entry points above already carry their types, so most code never imports from here.
 
import { div, fragment } from 'fiorejs';
import { circle, svg } from 'fiorejs/svg';
import { math, mi } from 'fiorejs/math';
import { html } from 'fiorejs/global';

document.body.append(
  div('Plain tags'),
  svg.attrs({ viewBox: '0 0 10 10' }).create(circle.attrs({ r: '4' }).create()),
  math(mi('x')),
  fragment([html.span('From the global entry')]),
);

SVG and MathML tags share some names with HTML, such as a and title. Import them as a namespace when you use both; see SVG and MathML. fiorejs/global is meant for code that wants the three namespaces as objects, such as html.div and svg.circle.

In JSX you import no tags: <div> and <svg> in the markup are enough, and the names that clash in the builder do not clash. JSX has no MathML tags, so import the nodes from fiorejs/math when you need MathML; see SVG and MathML.

Use without a bundler

Browsers load ES modules natively. An import map tells the browser where a bare name such as fiorejs lives, and a CDN serves the files. This page works as it is, with nothing installed: 

<script type="importmap">
  {
    "imports": {
      "fiorejs": "https://cdn.jsdelivr.net/npm/fiorejs@2.1.0/lib/html.js",
      "fiorejs/svg": "https://cdn.jsdelivr.net/npm/fiorejs@2.1.0/lib/svg.js",
      "fiorejs/math": "https://cdn.jsdelivr.net/npm/fiorejs@2.1.0/lib/math.js",
      "@fiorejs/signals": "https://cdn.jsdelivr.net/npm/@fiorejs/signals@2.1.0/src/signals.js"
    }
  }
</script>
<script type="module">
  import { h1, button } from 'fiorejs';
  import { state } from '@fiorejs/signals';

  const count = state(0);
  document.body.append(
    h1(['Clicked ', count]),
    button.on({ click: () => count.update((n) => n + 1) }).create('Add one'),
  );
</script>

The import map must come before the first module script. Pin an exact version in the URL, as above, so that a new release never changes a deployed page. List only the entries the page uses. @fiorejs/signals imports fiorejs by name, so keep that entry in the map whenever you use signals.

Self-hosted files. The same map works with local copies. Point the entries at ./node_modules/fiorejs/lib/html.js and ./node_modules/@fiorejs/signals/src/signals.js and serve the folder with any static server. The no-build template of Create a project does this.
No JSX here. The browser cannot read JSX, so a page without a build step uses the builders. JSX needs a compiler or a bundler.

TypeScript

The declarations ship with the package, and there is nothing to install from @types. The subpath entry points need a module resolution that reads the exports field of a package. Use "moduleResolution": "bundler" for an app with a bundler, or "node16" or "nodenext" for Node. Include the DOM library, because the element types come from it: 

{
  "compilerOptions": {
    "target": "es2022",
    "module": "esnext",
    "moduleResolution": "bundler",
    "strict": true,
    "lib": ["es2022", "dom", "dom.iterable"]
  }
}

Every tag returns the exact element type. input gives HTMLInputElement, and circle from fiorejs/svg gives SVGCircleElement. For a function that accepts a modifier for any tag, use the HTMLModifier and SVGModifier types exported by the modules, as Builders shows.

A JSX expression is typed as Node, not as the element. Cast it when you need the element type: (<input />) as HTMLInputElement. The tags, props and listeners are still checked per element.
