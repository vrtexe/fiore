Quick start

Ownership and cleanup

Whatever an effect, a computed, a list row or a conditional branch creates belongs to it. When it runs again or goes away, what it created stops for good. You rarely write cleanup code; this page says when it happens and how to take control with root().

Owners

Effects, bindings, computed values and lists register with the owner that is running when they are created. When the owner reruns or stops, everything it owns stops, in the order it was created. These are owners:

  • an effect: what it creates stops before its next run and when it stops;
  • a computed that builds elements: its bindings and effects stop before it recalculates and when nothing reads it any more;
  • a signal.if or signal.case branch: what the old branch created stops when another branch is shown;
  • a list row: its bindings stop when the item leaves the array, and all rows stop when the effect or computed around the list reruns.

Effects created in effects

An effect created inside another effect is owned by it. When the outer effect runs again, the inner one is stopped and a new one is created by the new run. Without this, every rerun would leave one more live inner effect behind. 

import { state, effect, flush } from '@fiorejs/signals';

const room = state('a');
const message = state('hello');

effect(() => {
  const name = room.get();
  effect(() => console.log(name, message.get()));
}); // logs "a hello"

room.set('b');
flush(); // the old inner effect stops; logs "b hello"

message.set('bye');
flush(); // logs "b bye" once, not twice

onCleanup

Bindings and effects stop on their own, but a document listener, a timer or a node you added outside the element does not. onCleanup(fn) runs fn when the current owner stops: when a root is stopped, when a .if, .case or computed branch or a list row is removed, and before the next run of an effect, as well as when it stops. With no owner, it never runs. Call it while the owner runs, next to the code it undoes. 

import { div, p } from 'fiorejs';
import { flush, onCleanup, state } from '@fiorejs/signals';

const open = state(false);

function Panel() {
  const onKey = (event) => console.log('key', event.key);
  document.addEventListener('keydown', onKey);
  onCleanup(() => document.removeEventListener('keydown', onKey));
  return p('Panel');
}

document.body.append(div(open.if(() => Panel())));

open.set(true);
flush();
document.dispatchEvent(new KeyboardEvent('keydown', { key: 'Escape' })); // logs "key Escape"

open.set(false);
flush(); // the branch is gone, and the listener with it
document.dispatchEvent(new KeyboardEvent('keydown', { key: 'Escape' })); // logs nothing

An effect can also return its cleanup function, as Effects describes; onCleanup is for code that is not an effect body, such as a component or a list row.

A signal given as a ref in JSX, or to also in a builder, is a binding too: it holds the element while the element is in the document and is set to null for good when its owner stops, so an effect that reads it, for example to focus the element or to start a ResizeObserver it stops in its cleanup, runs again when the element is inserted or removed.

root()

root(fn) runs fn with an owner of its own and returns a function that stops everything fn created: effects, bindings, computeds and lists, inserted or not. Reads inside fn do not subscribe. A root belongs to no other owner, also when it is created inside an effect, so call its function yourself. If fn throws, what it created is stopped. 

import { div } from 'fiorejs';
import { root, state, effect, flush } from '@fiorejs/signals';

const count = state(0);

const dispose = root(() => {
  effect(() => console.log('count is', count.get()));
  document.body.append(div(count));
}); // logs "count is 0"

count.set(1);
flush(); // logs "count is 1"; the div shows 1

dispose();
count.set(2);
flush(); // logs nothing; the div still shows 1
console.log(document.body.textContent); // 1

A binding stopped by a root stays stopped, also when its element is inserted again. Use a root for the whole app, or for a view you mount and unmount yourself.

Removed elements

A binding also pauses while its element is out of the document. fiorejs watches the document with a MutationObserver. When an element is removed, its bindings pause; when it is inserted again, they resume with the current values. A live child among other children keeps its place between two comments, so it pauses and resumes also when its nodes are moved. A live child that is the only child follows its element. 

import { span } from 'fiorejs';
import { state, flush } from '@fiorejs/signals';

const count = state(0);
const label = span(count);
document.body.append(label);

label.remove();
await new Promise((resolve) => setTimeout(resolve)); // let the observer see the removal

count.set(1);
flush();
console.log(label.textContent); // 0: paused

document.body.append(label);
await new Promise((resolve) => setTimeout(resolve));
console.log(label.textContent); // 1: resumed with the current value
import { state, flush } from '@fiorejs/signals';

const count = state(0);
const label = <span>{count}</span>;
document.body.append(label);

label.remove();
await new Promise((resolve) => setTimeout(resolve)); // let the observer see the removal

count.set(1);
flush();
console.log(label.textContent); // 0: paused

document.body.append(label);
await new Promise((resolve) => setTimeout(resolve));
console.log(label.textContent); // 1: resumed with the current value

Pausing is not ownership. Content built outside any owner, for example view = state(Home()), is only paused when a live child replaces it and it leaves the document. Build it in a computed or a root to stop it for good. The observer does not see elements inside a shadow root, so their bindings are not paused.

Elements that are never inserted

An element that is created but never inserted keeps its bindings for as long as its signals live, unless it was created in a root that is disposed. Once the element and its signals are no longer referenced, everything can be garbage-collected. A resource stops with its owner: its load is aborted, as Async data describes.

Where code has no owner

An owner is only current while its code runs. Effects, bindings and computeds created where no owner is running are never stopped, and onCleanup called there never runs. These places have no owner:

  • event handlers, timers and other callbacks that run later;
  • in an async component or function, everything after the first await, because JavaScript cannot carry the owner across an await.

untrack(fn) is not on this list. It runs fn without subscribing to the signals it reads, but fn keeps the current owner, so what it creates stops with that owner: 

import { effect, flush, state, untrack } from '@fiorejs/signals';

const room = state('a');
const message = state('hello');

effect(() => {
  const name = room.get();
  untrack(() => {
    effect(() => console.log(name, message.get()));
  });
}); // logs "a hello"

room.set('b');
flush(); // the outer effect reran, so the old inner effect stopped: logs "b hello"

message.set('bye');
flush(); // logs "b bye" once, not twice

None of these places needs to create anything. An event handler sets a signal, and the view that reacts to it is already declared with .if, .case or .map. The branch or row owns what it builds, so closing it stops its effects and bindings: 

import { button, div, p } from 'fiorejs';
import { effect, flush, state } from '@fiorejs/signals';

const count = state(0);
const open = state(false);

function Panel() {
  effect(() => console.log('count is', count.get()));
  return p(count);
}

document.body.append(
  div([
    button.on({ click: () => open.set(true) }).create('Open'),
    open.if(() => Panel()),
  ]),
);

open.set(true);
flush(); // logs "count is 0"
count.set(1);
flush(); // logs "count is 1"

open.set(false);
flush(); // the branch is gone, and its effect with it
count.set(2);
flush(); // logs nothing

In an async component, create effects before the first await, or load the data with resource and show it with .if or a computed child, so everything is built synchronously under the right owner.
