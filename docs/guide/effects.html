Effects

An effect runs a function now and again after any signal it read has changed. Use it for work that leaves the signal graph, such as logging, timers, storage or calling a library. For values and DOM updates, prefer computed values and bindings.

effect(fn)

effect(fn) runs fn at once and subscribes to every signal it reads. When one of them changes, the effect runs again in the next flush. It returns a function that stops it. 

import { state, effect, flush } from '@fiorejs/signals';

const theme = state('light');

const stop = effect(() => {
  localStorage.setItem('theme', theme.get());
});

theme.set('dark');
flush();
console.log(localStorage.getItem('theme')); // dark

stop();
theme.set('light');
flush();
console.log(localStorage.getItem('theme')); // still dark: the effect is stopped

An effect reads only what it reads on its latest run, so its dependencies can change from run to run. It is never re-entered: a write inside the effect to a signal it reads schedules another run after the current one.

Cleanup

If fn returns a function, that function runs before the next run and when the effect stops. Use it to undo what the run set up, such as a listener or a timer. 

import { state, effect, flush } from '@fiorejs/signals';

const room = state('a');

const stop = effect(() => {
  const name = room.get();
  console.log('join', name);
  return () => console.log('leave', name);
});

room.set('b');
flush(); // leave a, join b
stop();  // leave b

Effects and bindings created inside an effect belong to it. They stop before the next run and when the effect stops; Ownership and cleanup describes the rules.

untrack and read

untrack(fn) runs fn without subscribing to the signals it reads. Use it when an effect should react to one signal but only look at another.

read(value) returns the current value of a signal, of a getter function or of a plain value. It lets one function accept all three, which is how components take Reactive<T> props. Inside an effect it subscribes like get() when the value is a signal. 

import { state, effect, flush, untrack, read } from '@fiorejs/signals';

const query = state('fiore');
const page = state(1);

effect(() => {
  // runs when query changes, not when page changes
  console.log('search', read(query), 'page', untrack(() => page.get()));
});

page.set(2);
flush();         // nothing runs
query.set('dom');
flush();         // logs "search dom page 2"

effect.pre and effect.post

effect.pre(fn) and effect.post(fn) take the same function and return the same stop function as effect. They differ in when they run inside a flush. pre effects run before the other effects and the bindings, so they can prepare state the rest reads. post effects run last, after the bindings have updated the DOM, so they can measure or focus elements.

The first run of effect.post waits for the next flush, not for the line after it. By then the element it was created with is usually in the document. 

import { div } from 'fiorejs';
import { state, effect, tick } from '@fiorejs/signals';

const label = state('first');
const box = div(label);
document.body.append(box);

effect.post(() => console.log('post sees', box.textContent, label.get()));
console.log('after creating the post effect'); // logs before the effect runs

await tick(); // logs "post sees first first"
label.set('second');
await tick(); // logs "post sees second second"

Timing and batching shows the order of the three phases.

Errors and loops

An effect that throws is stopped. The other effects of the flush still run, and at its end the flush throws the first error and reports the others with reportError. The error reaches the caller of flush() and rejects a waiting tick(); otherwise it is an uncaught error. An error in the first run of a new effect, outside a flush, is reported instead of thrown.

An effect that runs more than 100 times in one flush is stopped with an error in the same way. This usually means it sets a signal it reads. 

import { state, effect, tick } from '@fiorejs/signals';

const count = state(0);

// Reads and writes count, so every run queues the next one
effect(() => count.set(count.get() + 1));

try {
  await tick();
} catch (error) {
  console.log(error.message); // An effect ran more than 100 times in one flush; ...
}

To fix a loop, read the signal with untrack, or write to a different signal. If the value is derived, use a computed instead of an effect that writes.
